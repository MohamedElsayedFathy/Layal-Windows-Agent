# إمكانية الوصول والتنقل بلوحة المفاتيح — ليال

## النطاق والحالة

تغطي هذه المرحلة التنقل **داخل واجهة ليال نفسها** باستخدام لوحة المفاتيح، وإظهار موضع التركيز، وربط أسماء/تسميات عناصر الواجهة بواجهة Windows UI Automation. لا تنفّذ هذه المرحلة تحكم الوكيل العام بلوحة المفاتيح أو الماوس في التطبيقات الأخرى؛ ذلك مطلب مستقل ما زال غير منفذ بالكامل تحت `LAYAL-017`.

الحالة الحالية: **تنفيذ أولي في فرع مراجعة — غير متحقق على Windows**. لا يُعلن اكتمال إمكانية الوصول قبل نجاح البناء واختبارات القبول اليدوية وقارئ الشاشة.

## اختصارات لوحة المفاتيح المضافة

| الاختصار | الوظيفة |
|---|---|
| `Ctrl+1` أو `Ctrl+NumPad1` | الرئيسية |
| `Ctrl+2` أو `Ctrl+NumPad2` | المحادثة، مع نقل التركيز إلى حقل الرسالة |
| `Ctrl+3` أو `Ctrl+NumPad3` | المهام |
| `Ctrl+4` أو `Ctrl+NumPad4` | المهارات |
| `Ctrl+5` أو `Ctrl+NumPad5` | الكاميرات |
| `Ctrl+6` أو `Ctrl+NumPad6` | الذاكرة |
| `Ctrl+7` أو `Ctrl+NumPad7` | الإعدادات |
| `F1` | فتح دليل الاختصارات |
| `Alt` ثم مفتاح الوصول الظاهر تحته خط | فتح زر الاختصارات من لوحة المفاتيح |

تبقى طرق WPF المعتادة متاحة: `Tab` للتقدم عبر عناصر التركيز، و`Shift+Tab` للرجوع، والأسهم في التبويبات والقوائم وعناصر الاختيار، و`Space` لتبديل مربعات الاختيار. في حقل المحادثة يرسل `Enter` الرسالة.

عند استخدام اختصار تبويب، ينتقل التركيز إلى أول عنصر قابل للاستخدام داخله قدر الإمكان؛ ويذهب `Ctrl+2` مباشرة إلى محرر الرسالة. عناصر التبويبات غير المحتوية على عناصر تفاعل قابلة للتركيز تستخدم عنوان التبويب كخيار احتياطي.

## تغييرات المصدر

- إضافة مؤشر تركيز مرئي يستخدم لون التمييز النظامي في Windows بدل تعطيل `FocusVisualStyle`، مع حدود أوضح لعناصر الأزرار والقوائم والتبويبات وحقول الإدخال.
- إضافة `PreviewKeyDown` للنافذة الرئيسية لتنفيذ اختصارات التبويبات وفتح مساعدة `F1`.
- إضافة أسماء ونصوص مساعدة لعناصر UI Automation، وربط حقول عنوان API والنموذج ومفتاح API وعنوان/محتوى ملاحظة الذاكرة بتسمياتها المرئية.
- تحديث أسماء قارئ الشاشة ونصوص المساعدة عند التبديل بين العربية والإنجليزية.
- توسيع `tools/validate_project.py` ليتحقق من وجود معالج لوحة المفاتيح، واختصارات التبويبات، ومؤشر التركيز، وروابط التسميات؛ هذا فحص ساكن فقط ولا يثبت سلوك Windows الفعلي.

## بوابة التحقق المطلوبة على Windows

1. تشغيل `python tools/validate_project.py` والتأكد من نجاح الفحوص الساكنة.
2. تشغيل `powershell -ExecutionPolicy Bypass -File .\tools\VERIFY-LAYAL.ps1`، ثم التأكد من نجاح بناء Release و`dotnet test` في Windows CI.
3. استخدام التطبيق دون ماوس: التنقل من النافذة إلى أزرار الرأس، ثم بين التبويبات وداخل كل تبويب، والتحقق من إمكانية إكمال إجراءات المحادثة والمهام والمهارات والذاكرة والإعدادات.
4. تجربة اختصارات `Ctrl+1` إلى `Ctrl+7` من أماكن مختلفة داخل الواجهة، بما فيها الأرقام في الصف العلوي ولوحة الأرقام، والتحقق من موضع التركيز بعد كل انتقال.
5. تشغيل Narrator و/أو NVDA بالعربية والإنجليزية، والتأكد من نطق اسم كل حقل وغرضه، خصوصًا حقول الإعدادات والذاكرة وعناصر القوائم.
6. تشغيل Windows High Contrast، والتحقق من وضوح مؤشر التركيز دون الاعتماد على اللون وحده.
7. تكرار الاختبار على تحجيم عرض 100% و150% و200%، مع اتجاهي RTL وLTR، والتأكد من عدم قطع عناصر الواجهة أو ظهور مصيدة تركيز.

## معيار إعلان الاكتمال

يظل `LAYAL-037` بحالة **مصدر موجود — غير متحقق** حتى تُرفق نتيجة CI الناجحة وسجل قبول Windows لهذه النقاط. إنشاء اختصار أو اسم UI Automation في المصدر وحده لا يكفي لإثبات إمكانية الوصول الكاملة.
