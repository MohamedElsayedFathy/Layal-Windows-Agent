# بوابة أدلة القبول اليدوي للإصدار

**الحالة الحالية: NO-GO — كل بوابات القبول اليدوي تبدأ بحالة PENDING.**  
ملف [`RELEASE_GATE_EVIDENCE.json`](RELEASE_GATE_EVIDENCE.json) هو سجل التحقق الآلي؛ لا تغيّر الحالة إلى `APPROVED` إلا بعد تنفيذ اختبار حقيقي وحفظ أدلته. نجاح CI وحده لا يُغلق القبول اليدوي.

## البوابات المطلوبة

| المفتاح في JSON | المطلوب قبل الاعتماد |
|---|---|
| `windowsDesktopAndSessions` | قبول تشغيل التطبيق وتسجيل الدخول/الجلسات وسلوك النوافذ والبيانات على جهاز Windows نظيف |
| `screenReaderAndHighContrast` | اختبار Narrator أو NVDA، وسمة Windows High Contrast فعلية |
| `rtlLtrDisplayScaling` | مراجعة العربية والإنجليزية، RTL/LTR، ومقاييس العرض المتاحة 100/125/150/175% |
| `multiMonitorDpi` | اختبار فعلي على شاشتين بمقياسي DPI مختلفين، وتوثيق الانتقال بينهما بصريًا وتقنيًا |

كل بوابة تتطلب `status=APPROVED` واسم المراجع `reviewedBy` وتاريخًا بصيغة `YYYY-MM-DD` ومرجع دليل حقيقي في `evidence`. لا تستخدم أسماء عامة مثل “passed” بدل مسار/رابط إلى أدلة فعلية. لا تضف بيانات مستخدمين أو مفاتيح أو نصوص محادثات حساسة إلى الأدلة.

## طريقة الإغلاق بدون كسر ربط الأدلة بالنسخة المختبرة

1. ادمج تغييرات الكود المراد اختبارها أولًا، ثم سجّل SHA للـ commit على `main` الذي ستختبره.
2. نفّذ الاختبارات اليدوية وسجّل الأدلة في [سجل القبول الحي](WINDOWS_LIVE_ACCEPTANCE_REPORT_AR.md).
3. بعد نجاح الاختبارات، حدّث فقط `docs/RELEASE_GATE_EVIDENCE.json`: ضع SHA المختبَر في `testedCommitSha`، وأكمل بيانات البوابات الأربع. ارفع هذا كتغيير لاحق منفصل عن الكود المختبَر.
4. تحقّق أن commit الاعتماد لا يغيّر أي ملف آخر. مدقق البوابة يفحص أن SHA المختبَر سلف للـ commit المرشح وأن الفرق بعد الاختبار محصور في سجل الأدلة نفسه.
5. شغّل CI على commit الاعتماد، ثم لا تنشئ tag إصدار إلا بعد إغلاق بوابات الحقوق والترخيص والتوقيع أيضًا.

إذا تغيّر كود التطبيق أو أصوله أو سكربتات البناء بعد الاختبار، أعد الاختبارات اليدوية على نسخة جديدة وأعد ضبط البوابات إلى `PENDING`. يجب أن يظل هذا الملف `PENDING` الآن؛ لا نملك دليلًا على أن الاختبارات الفعلية المذكورة قد أُجريت.

## تحقق محلي

على نسخة كاملة من Git:

```powershell
python tools/validate_release_readiness.py --require-manual-acceptance --commit-sha (git rev-parse HEAD)
```

هذه الأداة تتحقق من اكتمال سجل الموافقة وتسلسل commits، لكنها لا تستطيع مشاهدة شاشة الاختبار أو التحقق من صدق دليل يقدمه المراجع. بوابات المشروع القانونية والتوقيع الموثوق تبقى مستقلة ولا يستبدلها هذا الملف.
