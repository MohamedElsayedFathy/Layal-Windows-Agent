# تجهيز وجمع مجموعة الكلام المحلية — Phase D1

**الحالة:** أداة تجهيز مساحة الجمع أضيفت في فرع `feat/phase-d-speech-corpus-intake-20261119`. مجموعة البداية ما زالت نصوصًا فقط. هذه المرحلة لا تحتوي تسجيلات فعلية أو موافقات أو transcripts معتمدة؛ لذلك لا توجد نتائج ASR أو WER/CER حتى الآن.

## 1. إنشاء مساحة جمع محلية

من جذر مستودع Layal، شغّل PowerShell:

```powershell
$CollectionDir = "D:\LayalSpeechEvaluation\Session-001"
python tools/evaluation/prepare_speech_collection.py --output-dir $CollectionDir
```

إذا كان المسار موجودًا بالفعل، تتوقف الأداة ولا تمسح محتوياته. استخدم مجلد جلسة جديدًا. ويمكن تغيير مصدر النصوص عبر `--seed-manifest` مع إبقاء الملف من نوع transcript-only.

تُنشأ البنية التالية خارج مستودع Git. لا تضبط الأداة صلاحيات Windows ACL ولا تشفّر الملفات؛ يرث المجلد الناتج صلاحيات المجلد الأب. اختر وجهة محلية لا يصل إليها إلا الأشخاص المخولون، ولا تستخدم مجلد شبكة أو مجلدًا مشتركًا:

```text
Session-001/
  speech-reference-set.json
  recording-sheet.csv
  README_AR.md
  CONSENT_FORM_AR.md
  audio/
```

- manifest نسخة محلية من مجموعة البداية ذات 30 حالة.
- CSV ورقة تسجيل متوافقة مع Excel وبها أسماء WAV المقترحة.
- نموذج الموافقة والقراءة التشغيلية جزء من المساحة الخاصة.
- مجلد audio فارغ عند الإنشاء.

تمنع الأداة إنشاء مساحة الجمع داخل المستودع، وترفض أي seed جذره معلّم كمسجل، أو يحتوي حقول metadata غير معروفة، أو حالة تتطلب الموافقة الصريحة غير مفعّلة. وترفض أي حالة معلّمة مسبقًا كمسجلة أو بها موافقة أو مراجعة أو فرضية ASR. وتعيد بناء manifest الناتج من الحقول المسموح بها فقط. لا تنشئ تسجيلًا أو موافقة أو اعتمادًا تلقائيًا.

## 2. الموافقة والخصوصية قبل التسجيل

لا تبدأ قبل استكمال نموذج `CONSENT_FORM_AR.md` وشرح النقاط للمتطوع وتسجيل موافقته الفعلية. يجب إكمال جهة المشروع ووسيلة التواصل ومكان التخزين ومن يمكنه الوصول ومدة الاحتفاظ وتاريخ الحذف وطريقة سحب الموافقة. لا تبدأ الجمع إذا كانت هذه المعلومات فارغة أو غير مفهومة.

النطاق الوحيد المطلوب هنا هو `research-evaluation` لتقييم تحويل الكلام إلى نص محليًا. ولا يشمل ذلك تدريب النماذج أو fine-tuning أو voice cloning أو النشر أو المشاركة الخارجية أو أي غرض آخر. لا تحول موافقة التقييم إلى موافقة عامة على استخدام الصوت.

احتفظ بنموذج الموافقة الذي يحمل الاسم/التوقيع في تخزين محلي آمن ومقيد الوصول، منفصلًا عن الصوت والـmanifest. استخدم معرّفات مستعارة فقط مثل `spk-001` و`rev-001`. لا تضع أسماء أو بريدًا أو هاتفًا أو توقيعًا أو بيانات تعريفية في CSV أو JSON أو Git أو PR. لا تضع التسجيلات في مجلد مشترك؛ الأداة لا تغيّر صلاحيات الوصول أو تشفّر مساحة العمل.

لا تجمع بيانات حساسة أو كلمات مرور أو أرقام بطاقات أو عناوين أو معلومات تخص أشخاصًا آخرين. المشاركة اختيارية، ويجب توضيح طريقة سحب الموافقة والحذف وفق سياسة الاحتفاظ التي تم شرحها. النموذج قالب تشغيلي أولي وليس استشارة قانونية.

## 3. تسجيل العينة

1. اتبع صفوف `recording-sheet.csv`، وسجّل جملة واحدة لكل ملف WAV.
2. سمِّ الملف باسم الحالة، مثل `eg-001.wav`، وضعه في `audio/`.
3. سجّل رمز المتحدث المستعار نفسه لكل عينة صادرة عن المتحدث ذاته؛ لا تستنتج أو تخزن معلومات ديموغرافية.
4. لا تقص أو تعالج الملف عبر خدمة ويب. احتفظ بنسخة محلية أصلية.
5. راجع الجودة: بداية ونهاية كاملتان، لا يوجد كلام لشخص آخر، ومستوى الصوت واضح من دون clipping.
6. إذا لم تُقرأ الجملة كما هي، فلا تفترض أن النص المطبوع هو التفريغ الصحيح؛ اعتمد ما سُمِع فعلًا بعد مراجعة بشرية.

**المواصفات المطلوبة:** PCM WAV، mono، 16,000 Hz، 16-bit، مدة أكبر من صفر وحتى 120 ثانية، وحجم لا يتجاوز 64 MiB. المسار في manifest يجب أن يكون نسبيًا مثل `audio/eg-001.wav`.

هذه المجموعة عبارة عن جمل مقروءة؛ لا تمثل محادثة عفوية أو مقاطعة أو end-of-turn أو ضوضاء ميدانية. اجمع لهذه الظواهر مجموعة منفصلة ببروتوكول واضح وموافقة تغطيها.

## 4. تحديث manifest بعد الفعل الحقيقي فقط

بعد موافقة حقيقية وتسجيل الملف، حدّث الحالة المقابلة في نسخة العمل المحلية. المثال التالي يوضح الشكل فقط؛ لا تنسخ الوقت أو الرموز كما هي:

```json
{
  "id": "eg-001",
  "locale": "ar-EG",
  "referenceText": "إزيك؟ عامل إيه النهارده؟",
  "recordingStatus": "recorded",
  "audioAsset": "audio/eg-001.wav",
  "speakerId": "spk-001",
  "consent": {
    "granted": true,
    "recordedAt": "<الوقت الحقيقي للموافقة بصيغة ISO-8601>",
    "scope": "research-evaluation"
  },
  "referenceReview": {
    "status": "pending"
  },
  "hypotheses": {}
}
```

لا تضع `consent.granted=true` إلا بعد الموافقة الفعلية. وقت `recordedAt` هو وقت الحصول على الموافقة، وليس وقت التسجيل إذا اختلفا. لا تضف حقول الهوية أو مكان الإقامة أو أي معلومات لا يحتاجها التقييم.

## 5. مراجعة النص المرجعي

- استمع للتسجيل كاملًا، ثم قارن النص بما قيل بالفعل.
- صحح الكلمات، والضمائر، والنفي، والأرقام، والأسماء المنطوقة؛ لا "تصلح" صياغة المتحدث إلى جملة أفصح.
- اترك حالة المراجعة `pending` حتى يعتمدها شخص راجع الصوت فعليًا.
- بعد الاعتماد فقط، استخدم:
  
```json
"referenceReview": {
  "status": "approved",
  "reviewerId": "rev-001",
  "reviewedAt": "<الوقت الحقيقي للمراجعة بصيغة ISO-8601>"
}
```

- لا تضع فرضيات ASR قبل اعتماد النص البشري، ولا تستخدم النص المطبوع آليًا كأنه transcript ذهبي.

## 6. الفحص والتقييم

بعد إضافة عينة واحدة على الأقل واستيفاء الموافقة ومراجعة النص، استخدم أوامر الفحص والتقييم الواردة في [دليل Whisper Benchmark](WHISPER_BENCHMARK_RUNNER_AR.md). ستتحقق الأداة من موارد Whisper المثبتة ومن بنية WAV والمسارات والموافقة وحالة مراجعة النص قبل التشغيل.

كل تقارير التفريغ وملفات scoring تحتوي على محتوى صوتي/نصي مشتق من المتحدث؛ احتفظ بها محليًا ولا ترفعها إلى GitHub أو PR. لا توجد نتيجة أداء صالحة حتى يكتمل تشغيل فعلي على WAV حقيقي ومرجع بشري معتمد، ثم تراجع الأخطاء خصوصًا النفي والأرقام والكلمات الإنجليزية داخل العربية.

## 7. سحب الموافقة وإنهاء الجلسة

عند سحب الموافقة، أوقف استخدام العينة، واتبع طريقة الحذف التي تم شرحها: أزل الصوت ومخرجاته وفرضياته من مساحة العمل والنسخ التابعة، وأزل مرجعه من manifest. احتفظ أو احذف نموذج الموافقة وفق الالتزام القانوني وسياسة الاحتفاظ التي تم إبلاغ المتطوع بها. لا تترك ملفات WAV أو transcript في المستودع أو نسخ PR أو artifacts عامة.
