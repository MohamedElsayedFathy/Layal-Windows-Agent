# تقييم ربط Hermes Agent مع Layal — إثبات مفهوم آمن

**الحالة:** تقييم معماري وخطة اختبار؛ لم يتم تغيير كود التشغيل أو واجهة المستخدم في هذه المرحلة.  
**المرجع الذي تمت مراجعته:** `main` عند commit `de1af0929df8f4271d7ff89709bf468398e0cf1f` (26 أكتوبر 2026).

## الخلاصة التنفيذية

Hermes قد يضيف طبقة وكيل جاهزة لإدارة الأدوات والمهام والذاكرة والمهارات، لكنه ليس بديلًا تلقائيًا عن كل مكونات Layal. لدى Layal بالفعل:

- محادثة نصية محلية عبر Ollama، ومزوّد سحابي اختياري متوافق مع OpenAI.
- بث ردود المحادثة النصية، وعميل لتحليل صور يختارها المستخدم عبر `image_url`.
- إدخال صوتي محلي عبر Whisper وTTS محلي عبر Piper، بالإضافة إلى مسار Realtime سحابي عبر WebSocket.
- وكيل مهام خاص بليال، واستدعاء أدواتها، وسجل المهام والمحادثات، وذاكرة مشفرة محليًا، وموافقات قبل الإجراءات ذات الأثر.

بناءً على ذلك، لا نوصي باستبدال الخدمات الموجودة دفعة واحدة. الأفضل إثبات التوافق على مراحل، ثم اتخاذ قرار مبني على اختبارات فعلية.

## ما كشفه فحص المصدر الحالي

- `OpenAiCompatibleClient.ChatStreamAsync` يرسل إلى `/chat/completions` ويعالج SSE.
- `OpenAiCompatibleClient.AnalyzeImageAsync` يرسل صورة يحددها المستخدم كـ data URL داخل `image_url` إلى `/chat/completions`.
- `MainWindow.xaml.cs` يوجّه المحادثة عبر مزود Layal الحالي أو الخدمة المحلية، ويستعمل عميل الصور نفسه، بينما مسار المهام يمر عبر `AgentOrchestrator.RunTaskAsync`.
- `AgentOrchestrator` يمرر تعريفات أدوات Layal إلى النموذج وينتظر `tool_calls` من واجهة Chat Completions، ثم ينفذ كل استدعاء من خلال `AgentToolExecutor` مع موافقات Layal.
- `VoiceConversationService` يتصل مباشرة بمزوّد Realtime، بينما الصوت المحلي منفصل ويعمل بأسلوب دور بعد دور.

## حاجز الأمان — قبل تشغيل خادم Hermes

وثائق Hermes تنص على أن API server يتيح مجموعة أدوات Hermes، بما فيها الطرفية وعمليات الملفات، وأن `API_SERVER_KEY` مطلوب حتى عند الربط على `127.0.0.1`. لذلك:

1. لا تشغّل الخادم على عنوان عام أو واجهة شبكة؛ استخدم loopback فقط.
2. لا تستخدم مفتاحًا افتراضيًا أو ثابتًا في المستودع. احفظ المفتاح محليًا فقط ولا ترسله إلى GitHub أو السجلات.
3. ابدأ بملف تعريف Hermes مستقل مخصص لتجربة Layal، لا بتغيير إعدادات Hermes التي تستخدمها لأي غرض آخر.
4. قبل أي طلب من Layal، راجع أدوات ملف التعريف المسموح بها عبر واجهة إعداد toolsets وواجهة `GET /v1/toolsets`. لا تواصل التجربة إذا كانت الأدوات ذات الأثر لا تزال مفعّلة دون حاجة.
5. لا تمرر مفاتيح Hermes أو البيانات الخاصة داخل محتوى المحادثة. لا تثق بمخرجات النموذج باعتبارها موافقة على إجراء.
6. لا تسمح لـ Hermes بتنفيذ أمر أو تعديل ملف على جهاز Layal خلال إثبات المفهوم الأولي. لا نكشف أدوات Layal لـ Hermes قبل تصميم جسر موافقات واضح.

إذا لم نتمكن من الحصول على مجموعة أدوات محدودة ومتحقق منها في ملف التعريف المخصص، نتوقف عند تجربة API معزولة بدل وصل الوكيل كامل الصلاحيات.

## مراحل التنفيذ المقترحة

### المرحلة 0 — تدقيق التوافق (مكتملة على مستوى قراءة المصدر والتوثيق)

- راجعنا الخدمات الحالية وعقود API التي يتوقعها كل مسار.
- حددنا تعارضًا معماريًا بين أدوات Hermes وأسلوب موافقات `AgentOrchestrator`.
- أُضيف اختبار وحدة يعيد محاكاة SSE يحتوي تعليقات keep-alive وأحداث `hermes.tool.progress`، للتحقق من أن العميل الحالي يتجاهل هذه الإطارات غير النصية ويحتفظ بتجزئة الرد القياسية.
- اختبار الوحدة يستخدم endpoint وهميًا؛ لا يُعد اتصالًا حيًا بخادم Hermes، ولم يتغير كود تشغيل التطبيق أو واجهته.

### المرحلة 1 — إثبات مفهوم النص والصورة فقط

1. جهّز Hermes ومزود النموذج لديه مسبقًا، وتأكد من عمل محادثة من Hermes نفسه.
2. فعّل API Server في ملف تعريف تجريبي منفصل فقط، على `127.0.0.1`، مع مفتاح عشوائي قوي.
3. افحص `/health`, `/v1/models`, و`/v1/toolsets` باستخدام المفتاح محليًا؛ لا تسجل قيمة المفتاح في نتائج الاختبار.
4. في Layal، أنشئ اتصال API منفصلًا بعنوان الأساس `http://127.0.0.1:8642/v1` (أو المنفذ الذي اخترته)، والمصادقة Bearer بالمفتاح المحلي، ومعرّف النموذج الذي يعلن عنه Hermes مثل `hermes-agent`.
5. جرّب بالعناوين فقط محادثة عربية قصيرة، ومحادثة إنجليزية، ثم إكمال جولة ثانية للتأكد من بقاء السياق. راقب حالة HTTP، زمن الاستجابة، وتقطيع SSE.
6. أرسل PNG/JPEG غير حساس تختاره بنفسك مع سؤال بصري واضح. تحقق أن النموذج فعليًا يدعم الرؤية؛ فنجاح اتصال API لا يثبت دعم الصور.
7. اختبر المفتاح الخطأ، توقف الخادم، نموذجًا لا يدعم الصور، وإلغاء الطلب. يجب أن تظهر أخطاء واضحة ولا يسقط التطبيق أو يخزن الأسرار في سجل المحادثة.
8. عند النجاح، سجّل نتائج كل حالة دون إدخال المفتاح أو محتوى خاص في السجل.

**معيار القبول:** النص العربي والإنجليزي والصورة تعمل من داخل Layal، والواجهة تظل مستجيبة، والجلسات لا تتداخل، وأخطاء المصادقة/الرؤية/التوقف تفشل بوضوح. لا تعتبر المرحلة ناجحة حتى تجربها على Windows حقيقي مع نسخة Hermes الفعلية.

### المرحلة 2 — مهام الوكيل (لا تبدأ قبل اجتياز المرحلة 1)

لا نستخدم `/v1/chat/completions` لتشغيل `AgentOrchestrator` كما هو؛ Hermes لا يعيد أدوات Layal المرسلة له في `tools`. يجب بناء طبقة منفصلة تستخدم واجهة Runs/Responses أو جلسات Hermes الرسمية، وتعرض حالات التشغيل والإلغاء وفشل المهام وموافقات Hermes داخل Layal.

قبل كتابة التنفيذ، نصمم نموذج تهديد ونقرر صراحةً هل ستبقى أدوات النظام محصورة في Hermes، أم ستُعرَض أدوات محددة من Layal عبر جسر MCP. لا توجد حاليًا طبقة MCP مكتملة في سجل متطلبات Layal. أي جسر مستقبلي يجب أن يستخدم allowlist، والموافقات المحلية لكل أثر، والمهل الزمنية، وتسجيل أحداث منقحًا من الأسرار، وإلغاءً فعليًا.

### المرحلة 3 — الصوت

- ابدأ بمسار متسلسل: ميكروفون Layal بموافقة صريحة → STT الحالي → رسالة إلى Hermes → نص الرد → TTS المحلي الحالي.
- تحقق من اللهجة المصرية/الفصحى/الإنجليزية، زمن الاستجابة، الإلغاء، وعدم رفع الصوت إلى السحابة دون موافقة منفصلة.
- لا تدّعِ أن هذا Full-duplex. إذا أردنا مقاطعة الكلام في أثناء رد المساعد، فهذه تجربة مستقلة تحتاج بروتوكولًا صوتيًا متوافقًا، ومزامنة للجلسات مع وكيل Hermes، واختبارات مقاطعة وميكروفون وسماعات.

## قائمة الاختبارات المطلوبة

- [ ] Hermes غير متاح: تعرض Layal خطأ اتصال قابلًا للفهم ويظل المزود المحلي يعمل.
- [ ] مفتاح غير صحيح: يرفض الخادم الطلب ولا يُطبع المفتاح في السجلات.
- [ ] محادثة عربية ثم سؤال متابعة: يحافظ على السياق المقصود.
- [ ] محادثة إنجليزية مع سؤال متابعة.
- [ ] صورة سليمة يختارها المستخدم: إجابة مرتبطة بمحتوى الصورة.
- [ ] نموذج نصي فقط أو صورة مرفوضة: رسالة صريحة دون اعتبار ذلك نجاحًا.
- [ ] تدفق SSE القياسي وحدث Hermes إضافي/تعليق keep-alive.
- [ ] إلغاء أثناء الاستجابة وإغلاق الخادم أثناء الطلب.
- [ ] تحقق من أن جلسات محادثتين لا تتشارك التاريخ.
- [ ] لا تُنفّذ أي أداة محلية في إثبات المفهوم.
- [ ] لاحقًا فقط: حالات `/v1/runs` للإلغاء، الموافقات، الفشل، وانقطاع/استعادة SSE.
- [ ] لاحقًا فقط: صوت عربي/إنجليزي، مقاطعة، جهاز ميكروفون مفقود، ومنع إرسال الصوت السحابي دون موافقة.
