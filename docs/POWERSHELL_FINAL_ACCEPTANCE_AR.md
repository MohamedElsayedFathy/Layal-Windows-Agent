# تشغيل القبول النهائي عبر PowerShell — Layal

## الهدف

يوفر `tools/Invoke-LayalFinalAcceptance.ps1` نقطة تشغيل واحدة لفحوص المشروع على Windows. يقرأ سجل المتطلبات `docs/REQUIREMENT_TRACEABILITY.csv` وسجل وظائف AYO، ويتأكد من اكتمال معرفات المتطلبات، ثم يشغّل فحوص المصدر وPowerShell وPython و.NET، واختبارات C#، وفحوص واجهة Windows الاختيارية، وحزمة التوزيع ودورة المثبت الاختيارية.

لا يعلن السكربت أن كل وظيفة مقبولة لمجرد نجاح الاختبارات العامة. فهو يحفظ مصفوفتَي LAYAL وAYO ويترك قرار كل متطلب معلقًا حتى يرتبط معيار قبوله بدليل مستقل مناسب.

## التشغيل الأساسي

من PowerShell 7 داخل نسخة Git كاملة من المستودع:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Invoke-LayalFinalAcceptance.ps1
```

هذا التشغيل ينفذ فحوص المصدر، والتحقق من صياغة جميع ملفات PowerShell، واختبارات Python، وNuGet restore/audit، وبناء Release، واختبارات C#، والتحقق من تقرير TRX. لا يتحكم في الماوس أو يثبت التطبيق افتراضيًا.

## القبول التفاعلي ودورة المثبت

للتشغيل الشامل على GitHub Actions أو داخل جهاز افتراضي Windows مخصص للاختبار:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Invoke-LayalFinalAcceptance.ps1 -RunDesktopIntegration -RunInstallerLifecycle
```

- اختبارات سطح المكتب تشغّل Layal وتستخدم إدخال Windows الفعلي لاختبار النقر الشفاف والسحب واختصارات لوحة المفاتيح ومعاينة GLB وتشخيص الشاشة/DPI. أغلق نسخ Layal الأخرى قبل التشغيل.
- دورة المثبت تنشئ تثبيتًا تجريبيًا، وترقية، وتراجعًا، وإزالة، وتفحص بقاء بيانات المستخدم والتنظيف. هذا اختبار تغييري؛ لا تشغله على حساب Windows الشخصي أو جهاز يحتوي تثبيت Layal مهمًا.
- خارج GitHub Actions، لا بد من إضافة `-ConfirmDisposableProfile` إلى الأمر التفاعلي/المُغيّر لإقرار استخدام حساب أو VM قابل للتخلص منه. لا يجعل هذا الخيار الجهاز آمنًا تلقائيًا؛ على المشغّل التأكد من أن البيئة مخصصة للاختبار.

سير العمل `.github/workflows/windows-final-acceptance.yml` يشغّل المجموعة الكاملة تلقائيًا على Windows عند فتح/تحديث PR ذي صلة، كما يمكن تشغيله يدويًا من GitHub Actions.

## ما الذي يتم فحصه؟

1. هوية الـ commit، إصدار PowerShell، .NET 10، وPython 3.
2. صياغة كل ملفات `.ps1` في المستودع باستخدام PowerShell AST parser.
3. تحقق XAML/C#/الموارد والهيكل، وتحقق التوزيع والتراخيص وسجل AYO ونظافة المصدر.
4. اختبارات Python، وNuGet restore، وتدقيق ثغرات الحزم المباشرة والانتقالية.
5. بناء Release، واختبارات C#، والتحقق من أن تقارير TRX تحتوي اختبارات منفذة فعلًا.
6. عند تفعيل `-RunDesktopIntegration`: النقر الشفاف، سحب الشخصية، التنقل والاختصارات بلوحة المفاتيح، معاينة GLB المتحركة، وتشخيص الشاشة/DPI.
7. عند تفعيل `-RunInstallerLifecycle`: إنشاء التوزيعة، التحقق من ملفاتها وتجزئاتها، حالة التوقيع المعلنة، دورة التثبيت/الترقية/التراجع/الإزالة، ثم التحقق المستقل من سلامة التوزيعة.

## بوابات لا يستطيع CI حسمها وحده

تبقى هذه العناصر معلقة في التقرير حتى تُختبر ببيئة حقيقية وتُرفق أدلتها:

- الميكروفون، السماعات، جودة STT/TTS، المقاطعة، وفصل/إعادة توصيل الأجهزة.
- الكاميرات الحقيقية، ONVIF، RTSP/RTSPS، الشبكة المحلية وبيانات اعتماد تجريبية.
- خدمات AI وOllama وواجهات REST وGmail/OAuth والحسابات الخارجية.
- Narrator أو NVDA، التباين العالي، مراجعة RTL/LTR البصرية، وتبديل اللغة على جميع النوافذ.
- شاشتان فعليتان بمقياسي DPI مختلفين، وقياس الأداء والذاكرة والاستقرار على جهاز موثق.
- مراجعة الآثار الفعلية لكل أداة من أدوات الوكيل عند قبول الموافقة ورفضها.

للقبول على جهاز Windows المستهدف، استخدم أيضًا `tools/Start-LayalLiveAcceptance.ps1` وفق `docs/WINDOWS_ACCEPTANCE_CHECKLIST_AR.md`. يتطلب هذا المسار artifact محددًا وSHA-256 وcommit مطابقًا ومعرّف جهاز وحساب اختبار منفصلًا؛ وينشئ سجل جلسة وملف checklist وأدلة قابلة للمراجعة.

## المخرجات

يحفظ كل تشغيل تقاريره في `artifacts/final-acceptance/<timestamp>/`:

- `final-acceptance-report.json`: النتائج والبيئة والقيود.
- `final-acceptance-report.md`: تقرير عربي قابل للقراءة.
- `requirement-acceptance-matrix.csv`: كل سجلات LAYAL.
- `ayo-feature-acceptance-matrix.csv`: وظائف AYO الـ33.
- مجلدات الفحوص الفرعية: سجلات stdout/stderr ونتائج JSON/CSV.
- `artifacts/final-acceptance-test-results/`: تقارير TRX.
- `artifacts/distribution/`: المثبت والحزمة المحمولة وSBOM وSHA-256 عند تشغيل دورة التوزيع.
