# سجل العيوب — Layal 0.5.2

هذا السجل يجمع المشاكل التي أبلغ عنها المستخدم أثناء تجربة التطبيق. تعني عبارة «الإصلاح في المصدر» أن التعديل أُدرج في الكود؛ ولا تُغلق المشكلة نهائيًا قبل نجاح بناء Windows وتأكيد التجربة اليدوية.

| المعرّف | العَرَض المبلّغ عنه | المعالجة في المصدر | الحالة |
|---|---|---|---|
| BUG-01 | يصعب نسخ نتيجة المهمة كاملة لإرسالها للمراجعة | إضافة زر نسخ النتيجة وزر مستقل لنسخ سجل التنفيذ، مع رسالة تأكيد/خطأ | الإصلاح في المصدر؛ يلزم تحقق يدوي |
| BUG-02 | التمرير داخل نتيجة طويلة لا يعمل | جعل النتيجة مربع نص للقراءة فقط مع التفاف النص وشريط تمرير رأسي | الإصلاح في المصدر؛ يلزم تحقق يدوي |
| BUG-03 | لا تثبت ليال اسمها ولا تعرف أن المستخدم هو مطوّر المشروع | استخدام System Prompt موحّد في المحادثة والمهام يعرّف ليال ويذكر أن المستخدم هو مطوّر المشروع ومالكه دون اختلاق اسم | الإصلاح في المصدر؛ يلزم تحقق يدوي |
| BUG-04 | تفاعل الماوس ضعيف، والعينان لا تتبعان المؤشر، وقد تبقى الشخصية في وضع التفكير بعد المهمة | إضافة تتبع حركة المؤشر بالعينين، وتعبير الفضول عند المرور في حالة الخمول، وإرجاع حالات النجاح/الخطأ/الإيقاف إلى الخمول تلقائيًا؛ معالجة الاستثناءات واستعادة الحالة النهائية للمهمة | الإصلاح في المصدر؛ يلزم تحقق يدوي |

## تحقق الإصلاحات

1. يجب أن ينجح GitHub Actions في فحص المصدر وبناء Release وتشغيل الاختبارات.
2. داخل التطبيق، جرّب تحريك المؤشر فوق الشخصية وتحريك المؤشر داخل حدودها وخارجها أثناء الخمول وأثناء مهمة.
3. بعد مهمة ناجحة، يجب أن تعرض الشخصية تعبير النجاح مؤقتًا ثم تعود إلى الخمول؛ وبعد الإلغاء أو الخطأ تتبع النتيجة حالة الإيقاف أو الخطأ مؤقتًا ثم تعود للخمول.
4. جرّب نتيجة طويلة: تحقّق من التمرير داخل مربع النتيجة ونسخ النتيجة وسجل التنفيذ كلٌ على حدة.
5. اسأل ليال في المحادثة وفي تبويب المهام: «ما اسمك؟ ومن يطوّر مشروع ليال؟» وتحقق من أن الإجابة متسقة.
