# قبول إمكانية الوصول اليدوي — Layal Windows

**حالة إغلاق Phase B: USER-ACCEPTED (2026-11-18).** بناءً على طلب صريح من مالك المشروع، تم قبول المتبقي من اختبار الوصول إلى Complete Setup لإغلاق Phase B على أساس افتراضي. هذا اعتماد/تنازل من المالك، وليس تقرير اختبار PASS ولا إثباتًا مستقلًا لجودة نطق قارئات الشاشة أو التباين المرئي.

- **تم تأكيده يدويًا بواسطة المستخدم:** وضوح مؤشر التركيز ومنطقية ترتيب Tab/Shift+Tab في معالج Complete Setup.
- **Narrator/NVDA وHigh Contrast:** قُبلت افتراضيًا بطلب المالك، لكن لا يوجد في الجلسة المسجلة فحص نطق/تباين مكتمل أو دليل بصري/صوتي مستقل.
- **نتيجة فاحص PowerShell:** INCOMPLETE / BLOCKED عند شرط الأمان؛ رصد Consent=On وStartEnabled=True وتوقف قبل تنفيذ بقية الفحوص. لم يطلق الفاحص Narrator ولم يبدّل High Contrast ولم يبدأ تنزيلًا.
- **النطاق:** يغلق هذا القرار Phase B فقط. تبقى اختبارات الوصول العامة الأخرى والقبول الحي الأوسع على Windows منفصلة.

لا تضع هذه البنود في خانة PASS اعتمادًا على هذا الاعتماد وحده. اعتماد Narrator/NVDA وHigh Contrast محصور في قبول معالج Phase B فقط؛ لا يشمل النافذة الرئيسية أو بقية الشاشات. استخدم حالة USER ACCEPTED لتمييز قرار المالك من النتيجة التقنية.

## اختبار قارئات الشاشة لحقول تكاملات API — PR #216 وPR #217

**النطاق:** النافذة الرئيسية، صفحة تكاملات API، حقول نموذج الاتصال العشرة. هذا الاختبار مستقل عن قبول معالج Complete Setup المذكور أعلاه. حالة جميع صفوف هذا الاختبار عند إضافته: **NOT TESTED**؛ لم يتم تسجيل أي نتيجة نطق فعلية في CI أو في جلسة Windows تفاعلية.

### تجهيز جلسة الاختبار

1. شغّل إصدار Windows من Layal المبني من `main` بعد commit `296a133c3b719b44956ab32435c094b785f0b3b8`، أو من commit أحدث يتضمنه. أغلق النسخ القديمة لتجنب اختبار ملف تنفيذي غير مقصود.
2. استخدم بيئة اختبار أو ملف مستخدم تجريبي. لا تدخل مفتاح API حقيقيًا، ولا تحفظ اتصالًا، ولا تضغط أزرار **اختبار الاتصال** أو **استخدام كـ API ليال**.
3. سجّل إصدار Windows ورقم البناء، وإصدار Layal وcommit SHA، واللغة، والثيم، ودقة الشاشة ونسبة DPI، واسم قارئ الشاشة وإصداره.
4. شغّل **Narrator** باستخدام `Win+Ctrl+Enter`، أو شغّل NVDA من اختصار البرنامج المثبت. اختبر كل قارئ على حدة، ولا تعتبر نجاح أحدهما دليلًا على الآخر.
5. من النافذة الرئيسية انتقل إلى صفحة تكاملات API باستخدام `Ctrl+7`. تنقّل بـ `Tab` حتى تصل إلى **إضافة اتصال جديد / Add connection**، ثم فعّله بـ `Enter`. لا تحفظ النموذج.
6. تنقّل داخل النموذج بـ `Tab`، ثم أعد المسار عكسيًا بـ `Shift+Tab`. كرّر الجولة بعد تغيير لغة التطبيق إلى الإنجليزية ثم العربية. أعد ضبط اللغة الأصلية بعد الاختبار.
7. نفّذ نفس الخطوات منفصلةً مع Narrator وNVDA. سجّل ما نُطق فعلًا، لا ما تتوقعه من النص المرئي أو من شجرة UI Automation.

### عناصر مجاورة يجب سماع أسمائها أثناء التنقل

تأكد من أن عناصر اختيار الصورة ومسحها وأزرار الحفظ واختبار الاتصال واستخدام الاتصال كـ API ليال لها أسماء مفهومة عند المرور عليها. هذه خطوة تحقق من الاسم فقط؛ لا تضغط أي زر ينفّذ اتصالًا خارجيًا أو يحفظ بيانات.

بالنسبة إلى قائمة **طريقة المصادقة**، تحقق أن القارئ يعلن الخيارات عند فتحها والتنقل بينها، وأنه يعلن الاختيار الحالي. لا يلزم حفظ تغيير الاختيار؛ أغلق القائمة بعد الملاحظة.

بالنسبة إلى **حقل كلمة المرور**، اتركه فارغًا. تحقق من إعلان اسمه ونوعه دون إدخال أو ترديد أي سر. لا تضع رموزًا أو مفاتيح أو قيم ترويسات حقيقية في لقطات الشاشة أو التسجيلات أو ملف النتائج.

### معايير PASS لهذا الاختبار

- يعلن كل حقل باسمه الصحيح في اللغة الحالية، ولا يستخدم اسمًا عامًا مثل "edit" أو "text field" بدل الاسم.
- لا تبقى أسماء باللغة السابقة بعد تبديل العربية والإنجليزية.
- يعلن قارئ الشاشة نوع التحكم على نحو يساعد على فهم طريقة التعامل معه، ويظهر أن حقل صورة التطبيق للقراءة فقط.
- يُعلن اختيار قائمة المصادقة، وتبقى خياراتها قابلة للفهم والتنقل.
- يظل حقل السر حقل كلمة مرور، ولا يُكشف محتواه.
- يمكن الوصول إلى الحقول العشرة وإلى الأزرار المحيطة بها والعودة عبر `Shift+Tab` دون تخطٍ غير مبرر أو حبس تركيز.
- لا تُسجل نتيجة PASS إلا بعد سماع النطق الفعلي في القارئ المحدد واللغة المحددة.

### فاحص UI Automation المحلي لحقول API

يمكن تشغيل فاحص مساعد على سطح مكتب Windows بعد فتح صفحة **تكاملات API** والضغط على **إضافة اتصال جديد**، مع إبقاء نافذة Layal مفتوحة. لا يحتاج الفاحص إلى إدخال قيم في أي حقل، ولا يضغط أزرارًا، ولا يقرأ قيم الحقول أو أسرارها.

شغّل PowerShell 7 من جذر نسخة المستودع:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-LayalApiConnectionAccessibility.ps1 -ExpectedLanguage Arabic
```

بعد تغيير لغة Layal إلى الإنجليزية وإبقاء نموذج الاتصال مفتوحًا، شغّل:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-LayalApiConnectionAccessibility.ps1 -ExpectedLanguage English
```

يجب أن تكون Layal مفتوحة في نفس جلسة Windows التفاعلية، وأن تظهر عملية واحدة فقط باسم `Layal`. يمكن تحديد العملية صراحةً باستخدام `-ProcessId <PID>` عند وجود أكثر من نافذة. يرفض الفاحص العمل داخل GitHub Actions أو أي جلسة غير تفاعلية.

ينشئ الفاحص ملفي `api-screenreader-uia-report.json` و`api-screenreader-uia-fields.csv` داخل `artifacts\accessibility-api-uia\<timestamp>`. يفحص لكل حقل: `AutomationId`، والاسم المحلي، ونوع التحكم، وإمكانية التركيز بلوحة المفاتيح، وحالة الظهور والتفعيل. كما يتحقق من أن حقل صورة التطبيق للقراءة فقط وأن حقل المصادقة معلّم كحقل كلمة مرور. لا يقرأ خاصية `Value` لأي عنصر ولا يلتقط الشاشة.

**حدود هذا الفاحص:** نتيجة `PASS` تعني أن بيانات عناصر UI Automation المطلوبة موجودة ومتطابقة فقط. لا تعني أن Narrator أو NVDA نطق الاسم بشكل صحيح، ولا تختبر ترتيب النطق أو جودة اللغة أو التباين المرئي. يظل حقلا `NarratorSpokenOutput` و`NvdaSpokenOutput` في التقرير `NOT TESTED` دائمًا؛ يجب أن يستمع المختبِر فعليًا ويسجل نتيجة كل قارئ وكل لغة في الجدول أعلاه.

## معايير تسجيل النتيجة

استخدم واحدة من الحالات: **PASS**، **FAIL**، **BLOCKED**، **NOT TESTED**، أو **USER ACCEPTED (ASSUMED; NOT INDEPENDENTLY VERIFIED)**. الحالة الأخيرة توثق تنازل/اعتماد المالك فقط، ولا تعادل PASS ولا تثبت اختبار Narrator/NVDA أو High Contrast. لا تسجّل A11Y-06/07/08 أو A11Y-13/14 PASS من خلال قراءة شجرة UI Automation وحدها؛ يلزم الاستماع إلى النطق ومشاهدة التباين الفعلي. أرفق وصفًا محددًا ولقطة/تسجيلًا عند وجود خلل، ولا تضع بيانات حساسة داخل دليل الاختبار.

## اختبارات معالج Complete Setup الآلية

أضيف اختبار WPF آلي مستقل يفتح معالج Complete Setup على Windows، ويتحقق من أسماء عناصر الموافقة والتقدم والحالة والتشخيص واختيار مجلد الموارد، ويفحص اتجاه RTL/LTR، ويستدعي تحديث موارد High Contrast على نافذة مفتوحة. نجاح هذا الاختبار يثبت وجود الأسماء والموارد البرمجية فقط؛ ولا يحوّل A11Y-06 أو A11Y-07 أو A11Y-08 أو A11Y-13 أو A11Y-14 إلى PASS. يجب إبقاء هذه الحالات NOT TESTED حتى يُنفذ الاختبار البشري على سطح مكتب Windows وتُرفق الملاحظات/الأدلة المطلوبة.

### فحص معالج Complete Setup بواسطة PowerShell

بعد تشغيل معالج Complete Setup في مجلد الجلسة المعزول، يمكن تشغيل الفاحص التالي من جذر المستودع في نافذة PowerShell أخرى:

```powershell
.\tools\Test-LayalCompleteSetupAccessibility.ps1 `
    -SessionDirectory ".\artifacts\windows-live-acceptance\<session-folder>" `
    -LaunchNarrator `
    -ExerciseHighContrast
```

يفحص السكربت عملية Layal المطابقة لملف `portable-extracted\Layal.exe` داخل الجلسة، وأسماء UI Automation وأنواع عناصر الموافقة والأزرار والحالة والتشخيص، ويتأكد من أن الموافقة غير محددة وزر الإعداد الكامل معطل. ثم ينفذ Tab وShift+Tab، ويسجل العناصر التي تلقت التركيز، ويلتقط صورة عادية وصورة أثناء تفعيل Windows High Contrast مؤقتًا. يعيد السكربت حالة High Contrast الأصلية في كتلة `finally`، ولا يطلب موافقة الإعداد أو يبدأ تنزيلًا.

ينشئ السكربت `complete-setup-accessibility-report.json` وملفي CSV وصور PNG داخل مجلد الأدلة. خيار `-LaunchNarrator` يشغل Narrator إن لم يكن مفتوحًا؛ لكنه لا يستطيع إثبات ما سمعه المستخدم أو جودة النطق. وخيار `-ExerciseHighContrast` يغير حالة High Contrast مؤقتًا على مستوى جلسة Windows ثم يستعيدها؛ افحص الصورة الناتجة بصريًا بعد التشغيل.

في جلسة القبول الحالية لم يكتمل تشغيل السكربت: توقف قبل أي فحص لأن الموافقة كانت مفعّلة وزر بدء الإعداد متاحًا. لذلك لم يشغّل Narrator ولم يبدّل High Contrast ولم يصدر حكمًا آليًا. وبناءً على قرار المالك، سُجلت A11Y-06 وA11Y-07 وA11Y-08 وA11Y-14 كـ USER ACCEPTED (ASSUMED; NOT INDEPENDENTLY VERIFIED)، وسُجلت A11Y-13 مع فصل تأكيد لوحة المفاتيح عن جزء قارئ الشاشة المفترض. لا تغيّر هذا إلى PASS إلا بعد تنفيذ مستقل وإرفاق الدليل.

## حدود الأدلة المتاحة في المستودع

- اختبار Windows الآلي يفحص اختصارات التنقل، نقل التركيز إلى حقل الرسالة، وحوار F1، ويصدر ملفي JSON/CSV.
- اختبار GLB الآلي يفحص وجود النموذج والهيكل/الحركة وتقدم إطارات العرض.
- لا يثبت أي من الاختبارين جودة النطق، قابلية القراءة في التباين العالي، أو الملاءمة البصرية على أجهزة فعلية.
- يجب إبقاء كل البنود اليدوية غير المنفذة NOT TESTED حتى يسجلها مشغل بشري من سطح مكتب Windows.
