# نموذج تهديد مساحة العمل واستيراد المهارات — Layal

**النطاق:** نموذج تهديد للمرحلة الثانية. التغييرات البرمجية في هذا PR تخص استيراد حزم المهارات والتحقق من الفهرس ومسارات الحزم داخل `SkillPackageService`. أما ضوابط Workspace المذكورة هنا فهي السلوك الموجود بالفعل في `WorkspaceSnapshotService`؛ هذا PR يوثقها ولا يغيّر تنفيذها. يصف المستند الضوابط وحدودها ولا يمثل اعتمادًا أمنيًا مستقلًا أو شهادة بأن التطبيق خالٍ من الثغرات.

## الأصول والحدود

| الأصل | مصدر الثقة | ما يجب افتراضه |
|---|---|---|
| ملف مهارة ZIP محلي | يختاره المستخدم أو يصل من خارج التطبيق | غير موثوق بالكامل؛ قد يحتوي على مسارات خبيثة أو عناصر مضغوطة ضخمة أو أسماء متصادمة |
| أرشيف GitHub عام | مستودع وفرع خارجيان | المحتوى غير موثوق، والفرع قابل للتغيير، والتنزيل لا يثبت هوية مؤلف أو توقيعًا |
| `skills-index.json` وحزم المهارات المثبتة | ملفات محلية قابلة للتغيير بصلاحية حساب Windows | لا تُعامل قيمة مسار مخزنة على أنها موثوقة دون إعادة التحقق |
| نص `SKILL.md` والمراجع | محتوى يختاره المستخدم ويُمرّر كسياق إلى نموذج AI | قد يحمل تعليمات مضللة أو prompt injection؛ ليس كودًا آمنًا لمجرد اجتيازه تحليل YAML |
| ملفات Workspace ونسخها الاحتياطية | مجلد محلي وملفات JSON يمكن استيرادها | بيانات خارجية قد تستهدف traversal أو الاستبدال أو التلاعب بالمحتوى |
| بيانات المهام والذاكرة المحمية | مخازن محلية مرتبطة بحساب Windows | الاستيراد يجب أن يتحقق من جميع السجلات قبل تغيير أي مخزن |

## التهديدات والضوابط

| المعرّف | التهديد | الضوابط |
|---|---|---|
| SKILL-01 | استبدال ملف ZIP بين التحقق والتثبيت (TOCTOU) | ينسخ المستورد المصدر من مقبض ملف واحد إلى ملف مرحلي جديد داخل جذر المكتبة؛ يجري التحقق والتثبيت من البايتات المرحلية نفسها. |
| SKILL-02 | اجتياز المسارات أو استخدام مسارات Windows خاصة | رفض المسارات المطلقة والجذرية، و`.` و`..` والفواصل العكسية والمقاطع الفارغة، والنقط/المسافات النهائية، وأسماء الأجهزة المحجوزة وNTFS alternate data streams؛ ويُرفض اسم المهارة المحجوز كذلك في front matter والفهرس والسجل قبل إنشاء مساره أو قراءته. |
| SKILL-03 | ZIP bomb أو استنزاف الموارد | سقف 50 MiB للأرشيف المضغوط، و200 عنصر، و5 MiB لكل ملف بعد فك الضغط، و10 MiB إجمالًا؛ تُستهلك تدفقات العناصر ضمن سقف فعلي وليس بالاعتماد على بيانات ZIP الوصفية وحدها. |
| SKILL-04 | روابط رمزية أو عناصر ملفات خاصة | رفض Unix symlink والأنواع الخاصة، وفحص مكونات المسارات الموجودة بحثًا عن Windows reparse points قبل الوصول إلى الكتالوج أو الحزمة. |
| SKILL-05 | تصادم الأسماء أو اختلاف تفسير المسارات بين Windows والأنظمة الأخرى | رفض التكرار غير الحساس لحالة الأحرف، وتعارض الملف مع دليل أو مع مسار أبنائه، ورفض تعدد ملفات `SKILL.md` داخل الحزمة. |
| SKILL-06 | تزوير مسار حزمة في الفهرس أو تمرير سجل بحزمة خارج المكتبة | يعاد اشتقاق المسار المتوقع من اسم المهارة والتحقق من تطابقه مع المسار المخزن؛ يُفحص المسار حتى الملف قبل قراءته. |
| WS-01 | استعادة ملف خارج مساحة العمل أو فوق ملف موجود | مسارات نسبية canonical، فحص حدود Workspace، رفض المجلدات المحمية وأسماء أجهزة Windows وreparse points، والاستعادة create-new فقط دون overwrite. |
| WS-02 | استعادة محتوى تم التلاعب به | التحقق من Base64 والحجم وحدود العدد والإجمالي وبصمة SHA-256 قبل تعديل السجلات أو كتابة الملفات. |
| WS-03 | فشل جزئي أثناء الاستيراد | التحقق المسبق من مجموعتي المهام والذاكرة، ثم تسجيل المعرفات والملفات المنشأة ومحاولة rollback التعويضي عند الفشل. |

## قواعد التشغيل

1. حزم المهارات لا تُفك إلى مجلد تشغيل ولا تُنفّذ سكربتاتها. تخزين ZIP أو قبول front matter لا يمنح محتواه الثقة.
2. يجب أن يظل نص المهارة مرجعًا غير موثوق بالنسبة إلى النموذج. موافقات الأدوات وحدود مساحة العمل تظل مستقلة؛ نص المهارة لا يستطيع منح موافقة أو توسيع صلاحيات الأداة.
3. استيراد ملف Workspace احتياطي لا يعني تشغيل الملفات المستعادة أو فتحها. استعادة الملفات اختيار منفصل، والمحتوى يُكتب إلى ملفات جديدة فقط بعد التحقق.
4. النسخ الاحتياطية التي تتضمن محتوى ملفات تكون JSON غير مشفر؛ يجب أن يراجع المستخدم المحتوى ويحفظها في وجهة يثق بها.
5. لا تختبر على مساحة عمل تحتوي على بيانات حساسة عند إجراء اختبارات استيراد أو traversal؛ استخدم مجلدًا مؤقتًا وملفات اصطناعية.

## حدود متبقية

- لا يوفّر هذا التغيير sandbox لتشغيل مهارات أو عزلًا للعملية. تشغيل السكربتات يظل غير مدعوم حتى يُصمم حد عزل حقيقي ويُختبر.
- المحتوى النصي للمهارة قد يظل محاولة prompt injection. لا يمكن اعتبار قراءة النموذج له تنفيذًا آمنًا أو ضمانًا بأنه سيتجاهل التعليمات العدائية؛ لذلك يجب أن تبقى الأدوات والموافقات هي حد الصلاحية.
- أرشيف GitHub العام لا يُثبّت إلى commit SHA في هذا المسار الحالي، ولا يجري التحقق من توقيع مؤلف أو provenance attestations. الحماية الحالية هي تحقق بنيوي وحدود موارد، لا إثبات مصدر.
- فحص reparse points هو فحص لمسارات موجودة قبل عمليات الملف، وليس واجهة ملفات handle-relative مقاومة لكل سباقات متزامنة على مستوى النظام. لا يحمي من مسؤول نظام أو برمجية تعمل بصلاحية حساب المستخدم نفسه.
- لا تضمن هذه الضوابط عدم وجود ثغرات في .NET أو Windows أو مزود AI أو مكتبات فك الضغط.
- لم تُغلق بوابات القبول اليدوي على Windows، وقارئ الشاشة/High Contrast/DPI، ولا بوابات الترخيص والتوقيع الرقمي للإصدار.

## أدلة القبول المطلوبة

- Windows Release build والاختبارات الآلية الكاملة على نفس commit المرشح للدمج.
- تشغيل اختبارات ZIP العدائية ومسارات الحزم على Windows x64 مع نتائج دون skips غير مبررة.
- اختبار يدوي لاستيراد مهارة سليمة ورفض حزمة خبيثة، واستبدال نسخة موجودة مع rollback، واستعادة Workspace في مجلد مؤقت.
- توثيق إصدار Windows والـ commit SHA وسجلات الاختبارات، وعدم تسجيل أي أسرار أو محتوى خاص ضمن الأدلة.
