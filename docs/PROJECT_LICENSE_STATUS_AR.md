# حالة رخصة مشروع ليال والأصول

**الحالة الحالية: لم تُحدَّد رخصة للمشروع نفسه.** لا يوجد ملف LICENSE على مستوى جذر المستودع ولا إعلان آخر يحدد شروط الترخيص العام للمشروع.

هذا قرار يجب أن يصدر عن صاحب/أصحاب حقوق المشروع؛ لم تُضَف رخصة مفتوحة المصدر أو تجارية بالنيابة عنهم. إشعار حالة الرخصة المرفق بالحزمة لا يمنح أي حق في إعادة التوزيع أو التعديل أو الاستخدام التجاري لـ Layal نفسه. يجب اختيار الشروط وإضافة ملف LICENSE مناسب قبل النشر العام أو التجاري.

ملفات الأصول التالية موجودة في المستودع، لكن لا تحتوي شجرة المشروع الحالية على سجل مصدر أو رخصة/إذن استخدام لكل أصل:

## ما أُنجز في هذه المرحلة
- إضافة جرد واضح لاعتماديات NuGet الظاهرة في SBOM، ومراجع بيانات الرخص المنشورة لكل اعتماد.
- تضمين نصوص إشعارات WTFPL وMIT مع حزمة الاختبار، بدل الاكتفاء بذكر أسماء الرخص.
- إضافة فحص آلي يرفض حزم SBOM التي تحتوي على اعتماد غير موجود في سجل الرخص المعتمد للمراجعة.
- تفعيل تدقيق NuGet للمكتبات المباشرة والمتعدية وكشف الأسرار في تاريخ GitHub عبر CI.

## ما لا يمكن إغلاقه آليًا
- اختيار رخصة Layal نفسها واعتماد نصها من أصحاب الحقوق.
- إثبات منشأ الأصول الثلاثة وحق استخدامها في التوزيع.
- مراجعة توافق الرخص مع نموذج التوزيع التجاري/العام والإشعارات المطلوبة.
- توقيع الملفات بمفتاح موثوق والتحقق من سلسلة الثقة؛ هذا خارج نطاق فحوص التبعيات والرخص.

إلى أن تُحسم البنود القانونية أعلاه، تبقى الحزمة للتطوير والاختبار الداخلي ولا تُعد إصدارًا عامًا/تجاريًا معتمدًا.
