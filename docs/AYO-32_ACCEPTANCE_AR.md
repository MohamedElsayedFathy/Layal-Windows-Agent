# AYO-32 — وضع Incognito للمحادثات الخاصة

## السلوك المنفّذ

الوضع الخاص جلسة محادثة مؤقتة منفصلة عن سجل المحادثات العادي:

- يبدأ بمساحة محادثة فارغة؛ لا يحمّل نص المحادثة السابقة إلى نافذة الشات الخاصة.
- لا تُحفظ رسائل المستخدم أو ردود المساعد أو رسائل الحالة التي تضاف خلال الجلسة في ChatSessionService.
- عند الخروج، تُتلف مراجع جلسة الشات المؤقتة في واجهة التطبيق وتُستعاد آخر محادثة محفوظة دون حذفها أو تعديلها.
- إذا أُغلق التطبيق أو أُعيد تشغيله أثناء الوضع الخاص، لا توجد علامة Incognito محفوظة لإعادة فتح الجلسة؛ يبدأ التطبيق في الوضع العادي ويحمّل آخر سجل عادي محفوظ.
- لا تُحذف سجلات المحادثات أو المهام أو الذاكرة السابقة. تبقى مخازن Chat/Tasks/Memory المحمية كما هي، ويُعاد عرض بيانات المهام والذاكرة بعد الخروج.

## أسطح البيانات المحظورة أثناء Incognito

| السطح | السلوك أثناء الوضع الخاص |
|---|---|
| سجل المحادثات | إخفاء المحادثات المحفوظة وتعطيل اختيارها أو إنشاء/مسح محادثة محفوظة |
| حفظ الشات | منع حفظ أي رسالة جديدة في ChatSessionService |
| المهام | تعطيل تبويب المهام، مسح قائمة المهام والتفاصيل والسجل والتقدم من عناصر الواجهة |
| مهام الوكيل | منع بدء مهمة جديدة حتى لو استُدعي المعالج مباشرة |
| تفاصيل ونسخ المهام | منع إعادة عرض تفاصيل مهمة من callback قديم أو نسخ بياناتها إلى الحافظة |
| الذاكرة الشخصية | تعطيل تبويب الذاكرة ومسح المحرر والقائمة والعدادات ونتيجة الذاكرة |
| عمليات الذاكرة | منع القراءة والإنشاء والتعديل والأرشفة والحذف والاستيراد والتصدير والعلاقات وخريطة الذاكرة من مسارات الواجهة |
| Quick Ask وGmail | تعطيل الأزرار ورفض فتح التكاملين من معالجاتهما مباشرة |
| المتابعة الاستباقية | إيقاف قراءة سجل المهام والإشعارات السياقية وجدولة check-in مؤقتًا؛ تعود بعد الخروج |
| التذكيرات المنشأة يدويًا | تبقى محفوظة ومجدولة؛ فتح رابط مهمة منها يظل محجوبًا داخل الوضع الخاص |

## حدود الخصوصية

- الوضع يمنع الحفظ المحلي الجديد لرسائل هذه الجلسة، لكنه لا يمنع إرسال الرسالة التي يختار المستخدم إرسالها إلى مزود AI؛ يخضع ما يصل إلى المزود لسياسة السجلات والاحتفاظ الخاصة به، ولا يستطيع Layal سحبه بعد الإرسال.
- لا يُعد Incognito درعًا يمنع لقطات الشاشة أو الكاميرا أو التسجيل بحد ذاته؛ يظل لكل مصدر التقاط شرط الموافقة والسياسة المنفصلة، ويمكن استخدام مفتاح الخصوصية الشامل لمنع مصادر الالتقاط.
- لا يُجري التطبيق secure memory wipe لذاكرة .NET؛ إسقاط مراجع النصوص والصور المؤقتة لا يضمن الكتابة فوق كل نسخة في الذاكرة الفعلية أو ذاكرة النظام.
- لا تحذف الجلسة الخاصة أي محادثة أو مهمة أو ملاحظة سبق حفظها، ولا تمسح نسخًا سبق إرسالها لمزود خارجي أو نسخًا صدّرها المستخدم سابقًا.

## التحقق الآلي

- سياسة PrivateChatModePolicy موحدة لحماية سجل الشات والمهام والذاكرة وQuick Ask وGmail.
- اختبار WPF يزرع محادثة ومهمة وملاحظة محفوظة، ثم يتحقق من إخفائها مع بقاء بياناتها في المخازن دون تغيير.
- استدعاء مباشر قديم لتفاصيل مهمة لا يعيد النص إلى عناصر الواجهة، ومحاولة نسخ مهمة أثناء Incognito لا تغيّر الحافظة.
- محاولة استدعاء حفظ الذاكرة برمجيًا لا تضيف سجلًا أو تعدّل الموجود.
- تُضاف رسالة خاصة إلى نافذة الشات، ثم يُنشأ ChatSessionService جديد من نفس ملفات التخزين لمحاكاة إعادة تشغيل التطبيق؛ لا تظهر الرسالة الخاصة في السجل الجديد.
- بعد الخروج، تعود المحادثة العادية وسجل المهمة والملاحظة المحفوظة إلى الواجهة.
- ProactiveCheckInPolicy يرفض جدولة أو إصدار check-in أثناء privateChatActive.

## قبول Windows اليدوي

الحالة: **BLOCKED — يلزم اختبار يدوي على جهاز Windows مستهدف**.

1. الدخول والخروج والإلغاء عند سؤال التأكيد؛ والتأكد من أن النص العادي السابق لا يظهر داخل الجلسة الخاصة.
2. إرسال رسائل عادية ورسائل مع مرفق اختياري ثم إغلاق التطبيق قسرًا وإعادة تشغيله؛ لا تظهر رسالة خاصة في السجل المحفوظ.
3. فحص UI Automation وقارئ الشاشة للتأكد من عدم ظهور عناوين/محتويات المهام أو الملاحظات أو السجل المحفوظ داخل الوضع الخاص، بما في ذلك عناصر التبويب المعطّل.
4. محاولة الوصول إلى تبويب المهام والذاكرة وQuick Ask وGmail وفتح روابط إشعارات المهام أثناء Incognito؛ يجب أن تُرفض.
5. التحقق من بقاء المخازن المحلية المشفرة دون حذف، وظهور البيانات الأصلية مرة أخرى بعد الخروج.
6. تفعيل Incognito مع قرب موعد proactive check-in؛ يجب عدم تسليم إشعار متابعة خاص بسجل المهام أثناء الجلسة، ثم استئناف الجدولة بعد الخروج.
7. تجربة التذكير اليدوي أثناء الوضع الخاص؛ يمكن ظهور عنوان التذكير، لكن لا يجوز فتح المهمة المرتبطة أو عرض محتوى سجلها حتى الخروج.
8. اختبار RTL/LTR، لوحة المفاتيح، قارئ الشاشة، High Contrast، وإعادة تشغيل التطبيق.

نجاح CI سيؤكد منطق العزل في الكود وWPF smoke على عامل Windows، لكنه لا يُعد قبولًا يدويًا من جهاز المستخدم ولا يثبت سلوك كل قارئ شاشة/إشعار نظام فعلي.
