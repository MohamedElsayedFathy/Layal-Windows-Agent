# الساعة والتاريخ والطقس حسب موقع المستخدم

## السلوك وتجربة المستخدم

- يظهر الوقت والتاريخ والطقس في بطاقة السياق أعلى المحادثة، مع تحديث الساعة كل ثانية.
- **الإعداد الافتراضي يحترم الخصوصية:** تحديد الموقع التلقائي مغلق افتراضيًا. لا تستدعي Layal Windows Location Service عند أول تشغيل، ولا تطلب إذن Windows ولا ترسل إحداثيات قبل اختيار المستخدم «اكتشاف موقعي» وتأكيد الإفصاح.
- **موافقة الموقع على مرحلتين:** يعرض التطبيق أولًا شرحًا بأن إحداثيات تقريبية (دقة مستهدفة نحو كيلومتر واحد) سترسل إلى Open-Meteo لحساب الطقس والمنطقة الزمنية، ثم يطلب Windows إذن الموقع. يمكن رفض أي من المرحلتين دون تفعيل الموقع.
- بعد الموافقتين، يستخدم Windows Location Service عبر `Windows.Devices.Geolocation` بدقة تقريبية `DesiredAccuracyInMeters = 1000` ومهلة تحديد موقع 12 ثانية. لا يستخدم التطبيق تحديدًا عبر IP ولا reverse geocoding ولا يحاول استنتاج عنوان المنزل.
- تُرسل الإحداثيات إلى Open-Meteo Forecast API لجلب درجة الحرارة الحالية، والحرارة المحسوسة، والرطوبة، والرياح، ورمز الطقس والمنطقة الزمنية. لا تحفظ Layal خطوط الطول/العرض في `settings.json` أو Workspace أو سجل المحادثة.
- بعد نجاح الموافقة، يحفظ التطبيق **حالة الموافقة فقط** كي لا يكرر نافذة الإفصاح. يحفظ تفعيل الوضع التلقائي منفصلًا. لا يمكن تشغيل الطلب التلقائي عند بدء التشغيل أو مؤقت التحديث إلا إذا كان كلا الخيارين مفعّلًا.
- الإصدارات السابقة كانت تستخدم قيمة تلقائية افتراضية قد تكون حُفظت دون اختيار المستخدم. عند تحميل ملف إعدادات قديم بلا `AutomaticLocationConsentConfirmed`, يُلغى التفعيل التلقائي ويطلب التطبيق موافقة صريحة جديدة؛ تبقى المدينة اليدوية المحفوظة متاحة.
- يُحدّث الطقس كل 30 دقيقة أثناء تشغيل التطبيق، مع إمكانية التحديث يدويًا. بعد الموافقة فقط، يمكن إعادة قراءة الموقع عند دورة تحديث جديدة.
- تُحوّل الساعة إلى المنطقة الزمنية التي يعيدها Open-Meteo، مع fallback إلى UTC offset إذا تعذر تفسير معرّف المنطقة الزمنية. قبل تحميل تقرير الطقس، تستخدم الساعة المنطقة الزمنية المحلية لـ Windows.
- **المدينة اليدوية:** إدخال مدينة (حتى 120 محرفًا) واختيار «استخدام المدينة يدويًا» يعطّل الوضع التلقائي ويستخدم Geocoding API ثم Forecast API. لا يطلب هذا المسار إذن الموقع ولا يرسل إحداثيات الجهاز. مسح المدينة مع إبقاء الوضع اليدوي يعطّل تحديث الطقس حتى اختيار مصدر آخر.
- **عند رفض Windows للموقع:** يُعطّل الوضع التلقائي وتُزال موافقة الموقع المسجلة، ولا يعيد المؤقت الطلب. يمكن للمستخدم تفعيل خدمات الموقع في Windows ثم الضغط على «اكتشاف موقعي» مرة أخرى، أو استخدام مدينة يدويًا.
- **عند انقطاع الشبكة أو فشل المزود:** لا يخترع التطبيق درجة حرارة. إذا كان لديه تقرير سابق، يحتفظ به ويعرض تنبيهًا بأن البيانات قديمة؛ وإلا يعرض حالة تعذر التحديث مع خيار المدينة اليدوية.
- استجابات Open-Meteo محدودة بحجم 1 MiB بعد فك النقل، مع فحص Content-Length وحد القراءة الفعلية حتى لا تؤدي استجابة غير متوقعة أو chunked إلى استهلاك ذاكرة غير محدود.

## الخصوصية والاحتفاظ

- لا يوجد جمع للموقع عند بدء التشغيل قبل الموافقة الصريحة وWindows permission.
- الإحداثيات تُرسل مباشرة إلى Open-Meteo لغرض الطقس والمنطقة الزمنية فقط، ولا تُرسل إلى مزود AI.
- لا تُكتب الإحداثيات في ملف الإعدادات أو سجلات التطبيق ولا يتم إجراء reverse geocoding.
- اختيار المدينة اليدوية يعطل استخدام إحداثيات الجهاز؛ ولا يطلب أي إذن موقع.
- يمكن للمستخدم إيقاف الوضع التلقائي باختيار مدينة يدويًا. يجب إعادة اختيار «اكتشاف موقعي» لتفعيله من جديد.

## الاختبار الآلي

تستخدم اختبارات WeatherService استجابات HTTP اصطناعية للتحقق من بحث المدينة اليدوي، وقراءة الحرارة والرطوبة والرياح، وقراءة المنطقة الزمنية والإزاحة، وطلب الطقس باستخدام الإحداثيات المحددة دون geocoding، ورفض الإحداثيات والمدخلات غير الصحيحة، وحدود حجم استجابة المزود. وتتحقق اختبارات SettingsStore من أن الموقع التلقائي مغلق افتراضيًا، وأن إعدادات الإصدارات القديمة لا تتجاوز بوابة الموافقة الجديدة، وأن حالة الموافقة تُحفظ وتُستعاد في النسخ والتحميل.

الاختبارات الآلية لا تمنح إذن الموقع على جهاز المستخدم ولا تثبت جودة مستشعر Windows أو توفر مزود الطقس. يلزم قبول حي على Windows مع سيناريوهات السماح والرفض، والإنترنت/انقطاعه، وتغيير المدينة، والمنطقة الزمنية وDST.
