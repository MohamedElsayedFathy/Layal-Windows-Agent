# محرك السمع واللغة والحوار — الإصدار 2.1

## البنية ومسار الاستخدام الفعلي

يوفر مشروع `src/Layal.SpeechLanguage` مكتبة مستقلة عن WPF وNAudio وواجهات Windows. المضيف وحده يملك التقاط الصوت، واختيار الأجهزة، وطلب الموافقة، وإظهار التفريغ للمراجعة.

المسار الحالي:
1. تسجيل يدوي بعد إذن الميكروفون، وتحويل إلى WAV mono 16 kHz / 16-bit.
2. رفض حمولة غير RIFF/WAVE أو تتجاوز 64 MiB داخل `SpeechLanguageRuntime`.
3. التعرف المحلي عبر Whisper.cpp من خلال `LocalSpeechLanguageProvider`.
4. تحليل النص المكتشف عبر `SpeechLanguageEngine` والمرجع المحلي.
5. عرض التفريغ للمستخدم قبل إرساله إلى المحادثة؛ ولا يصبح transcript إذنًا لتنفيذ أمر.
6. تحويل الرد إلى كلام عبر VoiceTut المحلي بوضع Voice Design فقط.

لم يعد Piper محرك الإنتاج في هذا المسار. التكامل الحالي لا يستخدم reference audio ولا voice cloning ولا يضيف cloud fallback.

## تصنيف اللغة واللهجة — الإصدار 2.1

تتضمن النتائج:
- `EgyptianArabic`: عند وجود أدلة مصرية كافية.
- `ArabicStandard`: عند وجود أدلة فصحى كافية.
- `ArabicUnspecified`: عندما تكون اللغة عربية لكن الأدلة غير كافية أو متعارضة.
- `English` و`Mixed` للنص الإنجليزي أو المختلط.

### كيف يتم التصنيف

- أضيفت `dialectEvidenceWeight` إلى مدخلات المرجع اللغوي التي تمثل علامات لهجية مراجعة.
- تُطابق الأداة المصطلح وصِيَغه المسجلة فقط؛ لا تستخدم المرادفات الدلالية مثل «أريد» كأنها صيغة مصرية لمجرد ارتباطها بمعنى «عايز».
- تُجمع أوزان العلامات المختلفة، مع إزالة التكرار للصيغة ذاتها.
- يتطلب تصنيف المصرية أو الفصحى وزنًا لا يقل عن 3 مع فارق لا يقل عن نقطتين عن أدلة اللهجة المقابلة.
- الأدلة الضعيفة أو المتعارضة تعيد `ArabicUnspecified` بدل افتراض أن كل نص غير مصري هو فصحى.
- يعرض `DetectArabicDialect` الدرجات والعلامات المطابقة ودرجة الثقة لتسهيل تفسير النتيجة واختبارها.

هذه آلية معجمية قابلة للتفسير وليست نموذجًا صوتيًا لتحديد لهجة المتحدث. Whisper يفرغ الصوت؛ والتصنيف يحدث بعد التفريغ النصي. في النص المختلط تُصنف المقاطع العربية واللاتينية كلٌّ على حدة.

## ما تم اختباره آليًا

تغطي الاختبارات:
- تمييز المصرية عند وجود أكثر من علامة أو علامة قوية مسجلة.
- تمييز الفصحى من عدة علامات متوافقة.
- ترك النص العربي العام أو الملتبس دون تحديد اللهجة.
- الصيغ الكتابية المسجلة مثل «ازيك» و«عاوز».
- تصنيف المقاطع العربية والإنجليزية في النص المختلط.
- البحث عن المفردات والقواعد والأفعال والموضوعات وقوالب الرد.
- حدود WAV وحجم الصوت وحقن مزودي التعرف والنطق.

## الحدود التي لا تُغلقها الاختبارات الآلية

1. لا توجد حتى الآن مجموعة تسجيلات ذهبية بموافقة أصحابها وتفريغات بشرية معتمدة؛ لذلك لا ننشر رقم WER/CER.
2. يلزم اختبار ميكروفون وسماعة حقيقيين للعربية المصرية والفصحى والإنجليزية والمختلط.
3. VoiceTut هو محرك TTS الحالي، لكن النطق المصري الطبيعي ودعم الفصحى وثبات الهوية يحتاج تقييمًا سمعيًا؛ لا يصح إعلان اعتماد الصوت قبل ذلك.
4. لا يستخدم التحليل اللهجي لتنفيذ أمر أو تخطي Parser/Approval/Verification.
5. لا تعوض نتائج CI القبول اليدوي على Windows، بما يشمل إلغاء التسجيل وحذف الملفات المؤقتة وفحص أجهزة الإدخال والإخراج.

## بوابات التنفيذ التالية

- توسيع المرجع عبر دفعات لغوية مراجعة مع اختبارات رجعية، لا بمجرد زيادة عدد الكلمات.
- جمع عينات صوتية بموافقة محددة، وتثبيت تفريغ بشري قبل تشغيل قياس Whisper.
- اختبار مرشحي ASR وTTS على البيانات نفسها والأجهزة نفسها، دون تنزيل/استبدال تلقائي.
- إبقاء تسجيل الصوت يدويًا ومراجعته قبل تمرير النص إلى المحادثة أو مسار المهام.
