# قبول إمكانية الوصول والتنقل بلوحة المفاتيح — Layal 0.5.2

**الحالة الحالية: التنفيذ في المصدر + اختبار regression آلي؛ القبول اليدوي على Windows ما زال مطلوبًا.** لا تعتبر وجود مؤشر التركيز أو نجاح CI شهادةً وحدهما بالتوافق الكامل مع WCAG أو نجاح قارئ الشاشة.

## تغييرات المصدر

- إضافة حلقة تركيز موحّدة عالية الوضوح للأزرار والتبويبات وخانات الاختيار والمنزلقات وعناصر القوائم.
- زيادة سماكة حدود التركيز في حقول النص وكلمة المرور وصندوق الاختيار المنسدل.
- عدم إلغاء `FocusVisualStyle` على عناصر التحكم التفاعلية؛ الاستثناء الوحيد هو `GroupBox` غير القابل للتركيز في هذا التصميم.
- إضافة أسماء وأوصاف UI Automation للحقول التي لا يحمل محتواها المرئي اسمًا، وتحديث أسماء التبويبات وعناصر تبديل الواجهة حسب اللغة.
- ضبط التنقل الاتجاهي في شريط التبويبات ليعود إلى أوله/آخره عند الوصول إلى النهاية.

## خطوات القبول اليدوي

كرّر الاختبارات باللغتين العربية والإنجليزية، وفي المظهر الفاتح والداكن، باستخدام لوحة المفاتيح فقط قبل الانتقال إلى فحص قارئ الشاشة.

| الاختبار | الإجراء | النتيجة المتوقعة |
|---|---|---|
| الانتقال العام | استخدم `Tab` و`Shift+Tab` بدءًا من أعلى النافذة | ينتقل التركيز بترتيب منطقي، وتظهر حلقة التركيز بوضوح ولا يختفي التركيز داخل أي قسم |
| شريط الأقسام | ركّز على أحد التبويبات ثم استخدم الأسهم الاتجاهية | ينتقل التحديد بين الأقسام السبعة، ويظل التبويب الحالي واضحًا بصريًا |
| الأزرار | تنقّل إلى زر، ثم استخدم `Enter` أو `Space` | يظهر مؤشر التركيز ويُنفّذ الزر مرة واحدة |
| خانات الاختيار | ركّز على كل خانة واضغط `Space` | تتغير الحالة وتبقى قابلة للتمييز بصريًا |
| القوائم المنسدلة | افتح القائمة واستخدم الأسهم و`Enter` و`Escape` | يمكن استعراض الخيارات واختيارها أو إغلاق القائمة دون فقدان الموضع |
| القوائم والعناصر | تنقّل في المحادثات والمهارات والمهام والذاكرة | يظهر التركيز/التحديد على العنصر، ويمكن الوصول إلى عناصر القائمة دون الماوس |
| منزلقات الإعدادات | ركّز على الحجم والشفافية وعدّل الأسهم | يتغير المقدار ويمكن سماع/قراءة اسم المنزلق وقيمته عبر UI Automation |
| حقول الإدخال | ركّز على المحادثة والمهمة ورابط المهارة والذاكرة وحقول المزود | يعلن قارئ الشاشة اسم الحقل، ويكون اتجاه URL ومعرّف النموذج ومفتاح API من اليسار إلى اليمين |
| إيقاف التنفيذ | أثناء استجابة أو مهمة جارية، انتقل إلى زر الإيقاف | يصل إليه التركيز ويمكن تفعيله بلوحة المفاتيح |
| تبديل اللغة والثيم | استخدم عناصر التبديل ثم أعد المرور على عناصر التحكم | تتحدث التسميات وأسماء UI Automation ويظل مؤشر التركيز ظاهرًا |
| قارئ الشاشة | جرّب Windows Narrator؛ واستخدم NVDA إن كان ضمن بيئة الاختبار | تُقرأ أسماء التبويبات والحقول والأزرار والحالات المهمة بشكل مفهوم، دون تكرار مزعج أو عناصر مجهولة |

## قبول حالات التباين والحالات الفارغة

- اجعل نافذة ليال مفتوحة ثم فعّل Contrast theme من إعدادات Windows؛ يجب أن تتغير ألوان الخلفية والنص والتحديد دون إعادة تشغيل، ويظل النص مقروءًا في أقسام الواجهة.
- بدّل سمة Windows مرة أخرى وتأكد من رجوع لوحة الألوان الفاتحة/الداكنة.
- افتح التطبيق دون رسائل أو مهام أو مهارات أو ملاحظات، ثم أضف/احذف عناصرًا وتأكد أن رسائل الفراغ تظهر وتختفي تلقائيًا، بالعربية والإنجليزية.
- اختبر Narrator/NVDA للتأكد من أن أسماء القوائم وحالات التحديث واضحة؛ نجاح اختبار الموارد الآلي لا يثبت جودة النطق.

## تسجيل الأدلة

لكل بند سجّل: `PASS` أو `FAIL` أو `BLOCKED` أو `NOT TESTED`، مع نظام التشغيل وإصدار البناء واللغة والثيم وقارئ الشاشة (إن استُخدم). أرفق لقطة شاشة أو وصفًا دقيقًا للحركة عند وجود خلل في التركيز. لا تسجّل اختبار قارئ الشاشة نجاحًا إذا لم يتم تشغيله فعليًا.

## حدود التحقق الآلي

اختبار WPF في CI يحمي الموارد وأسماء UI Automation الأساسية من التراجع، لكنه لا يحكم على ترتيب التركيز الفعلي أثناء التشغيل ولا على جودة نطق قارئ الشاشة. يلزم تنفيذ الخطوات أعلاه على سطح مكتب Windows تفاعلي قبل إغلاق هذه المرحلة.

## اختبارات اختصارات PR #7 وPR #25

الـ PRين يشيران إلى نفس فرع المصدر ونفس commit للرأس (`2f7a1bc567c68e9005831b60351067a22024ef5d`)؛ لذلك فهما تغييران مكرران وليسا ميزتين مستقلتين. تُراجع الميزة مرة واحدة على أحدث `main`، ولا يُدمج أي من الفرعين القديمين مباشرةً لأنهما متأخران عن `main`.

نفّذ كل اختبار من أكثر من موضع داخل النافذة، بما في ذلك عندما يكون التركيز داخل حقل إدخال:

| الاختبار | الإجراء | النتيجة المطلوبة |
|---|---|---|
| مفاتيح الصف العلوي | اضغط `Ctrl+1` إلى `Ctrl+8` | ينتقل إلى القسم الصحيح دون تنفيذ إجراء غير مقصود |
| لوحة الأرقام | كرر باستخدام `Ctrl+NumPad1` إلى `Ctrl+NumPad8` | النتيجة نفسها لكل قسم |
| استعادة موضع التركيز | بعد كل انتقال، اضغط `Tab` و`Shift+Tab` | يبدأ التنقل من القسم المحدد، ولا يُفقد التركيز أو يُحاصر |
| قسم المحادثة | اضغط `Ctrl+2` ثم اكتب نصًا تجريبيًا | ينتقل التركيز إلى حقل الرسالة؛ لا ترسل رسالة دون ضغط `Enter` |
| المساعدة | اضغط `F1` ثم أغلق الحوار | تظهر المساعدة باللغة الحالية، ويعود التركيز إلى النافذة بصورة منطقية |
| عدم التعارض | اختبر `Ctrl+1..8` و`F1` مع مربعات الاختيار والقوائم والحقول | لا يحدث تغيير غير متوقع في قيمة أو عنصر آخر |
| إلغاء المهمة الصوتية/الإعداد | أثناء عملية قابلة للإلغاء اضغط `Escape` | تُلغى العملية المناسبة دون تعطيل التنقل الطبيعي في الحالات الأخرى |
