# خطة تنفيذ وتقييم السمع والكلام — العربية المصرية والفصحى والإنجليزية

**تاريخ المراجعة:** 13 نوفمبر 2026
**الوضع:** أساس الاختبارات وتقييم النماذج؛ لم يُعتمد بعد نموذج جديد للإنتاج.

## 1. خط الأساس الموجود في Layal

- تسجيل يدوي من الميكروفون باستخدام NAudio.
- تحويل التسجيل إلى WAV mono 16 kHz / 16-bit، ثم Whisper.cpp محليًا (ggml-base.bin متعدد اللغات، مع اللغة auto).
- تُعرض نتيجة التفريغ للمراجعة؛ مسار STT اليدوي لا يرسل النص تلقائيًا.
- مسار المحادثة الصوتية المحلية يمرر النص المستخرج إلى NativeConversationEngine بعد إيقاف التسجيل. التنفيذ الحالي لا يعمل Full-duplex.
- النطق المحلي باستخدام Piper؛ محرك النطق يقسم المقاطع العربية واللاتينية ويربط العربية بصوت ar_JO-kareem-medium والإنجليزية بصوت en_US-lessac-medium.
- تقسيم العربية/اللاتينية ليس دليلًا على صوت مصري؛ الصوت العربي الحالي ليس صوتًا مصريًا موثقًا.
- مسار إعدادات API القديم لا يجب اعتباره جزءًا من المسار الصوتي المحلي الحالي. لا يجوز رفع أي تسجيل لتقييم خارجي دون موافقة منفصلة ومحددة.

## 2. المرشحون — لا استبدال قبل الاختبار

| المهمة | المرشح | الترخيص المعلن | نقاط القوة | القيود والمخاطر | القرار |
|---|---|---|---|---|---|
| STT مصري ومختلط | [QwenCleo-ASR](https://huggingface.co/mohammedaly22/QwenCleo-ASR) | Apache-2.0 حسب بطاقة النموذج | دقيق في المصرية والانتقال عربي/إنجليزي وفق تقييمات الناشر؛ مبني على Qwen3-ASR-1.7B | نحو 1.7B parameters / BF16، ويتطلب مسار Python وموارد أكثر من Whisper base؛ الناشر يذكر أنه غير مثالي للإنجليزية الخالصة والضوضاء البعيدة؛ نتائج WER/CER ذاتية النشر وغير مستقلة | مرشح تقييم على جهاز مناسب، وليس default runtime |
| TTS مصري قاهري | [KemeTone](https://huggingface.co/Rabe3/kemetone) | Apache-2.0 حسب بطاقة النموذج | 81.8M، 327MB fp32، يذكر تشغيل CPU، صوت مصري قاهري | صوت أنثوي واحد، لا يدعم النص اللاتيني أو الأرقام أو code-switching؛ يعتمد على G2P وقاموسه الخاص والتشكيل يحسن النتائج | تجربة أولية منفصلة للمقاطع المصرية فقط |
| TTS مصري ومختلط | [VoiceTut-TTS](https://huggingface.co/mohammedaly22/VoiceTut-TTS/tree/v1) | Apache-2.0 حسب بطاقة النموذج | دعم المصرية وخلط العربية/الإنجليزية، أصوات مدمجة متعددة | يعتمد على OmniVoice/Qwen3 0.6B وتثبيت PyTorch؛ قياس الناشر على T4 أظهر قرابة 2.93GB VRAM، فلا يُفترض أنه مناسب لكل أجهزة Windows أو CPU | مرشح GPU اختياري بعد فحص الموارد والترخيص والتكامل |
| الأساس الحالي | whisper.cpp multilingual base + Piper | حسب ملفات وتبعيات المشروع الحالية | محلي وقائم بالفعل، أحجام موارد معروفة وبصمات تحقق موجودة | جودة المصرية وصوت النطق الحالي يحتاجان قياسًا مقابل مرشحين متخصصين | يبقى fallback الحالي حتى نجاح gate الاستبدال |

**ملاحظات القرار:**
- لا نختار QwenCleo من WER ذاتي النشر وحده؛ نعيد قياسه على نفس عينات Layal وبنفس شروط Whisper.
- لا ندمج KemeTone مع الإنجليزية داخل مقطع واحد؛ تُفصل المقاطع ويعالج كل محرك اللغة المدعومة فقط، وتُحفظ علامات الترقيم والأرقام.
- VoiceTut يعرض voice cloning ضمن الميزات؛ Layal لا تفعل استنساخ أصوات الأشخاص. يستخدم فقط صوتًا مدمجًا مرخصًا بعد مراجعة الملفات/التبعيات.
- كل تنزيلات النماذج يجب أن تكون بإصدار/commit ثابت وبصمات SHA-256 وبيان ترخيص.

## 4. مصفوفة التقييم الصوتي المطلوبة

لكل متحدث/متحدثة متطوع/ة وبموافقة واضحة، اجمع على الأقل 30–50 جملة لكل فئة أولية، ثم وسّعها إلى 100+ لكل فئة:

1. مصرية يومية: أسئلة، نفي، أفعال متصرفة، ضمائر، أرقام وأسماء أماكن.
2. فصحى: جمل رسمية، إعراب ونهايات، مصطلحات وقراءة نصوص.
3. إنجليزية: محادثة عامة، لهجات متعددة، كلمات تقنية وأسماء منتجات.
4. Mixed: إدخال أسماء التطبيقات/المصطلحات الإنجليزية داخل كلام مصري أو فصيح.
5. ظروف صوتية: هدوء، ضوضاء منزلية، ميكروفون قريب/بعيد، سرعة بطيئة وطبيعية وسريعة.
6. ظواهر الحوار: تردد، تصحيح الذات، مقاطعة، سؤال توضيحي، جملة غير مكتملة، حوار متبادل.

لا بد أن يحتوي كل ملف على transcript بشري معتمد، locale/variety، المتحدث برمز غير معرف، نوع الجهاز، ظروف التسجيل، مدة المقطع، وموافقة الاستخدام. لا تستخدم بيانات شخصية أو بيانات حساسة في مجموعة الاختبار.

## 5. المقاييس

- WER بعد تطبيع محافظ موثق، وCER للعربية.
- قياس منفصل للمصرية والفصحى والإنجليزية والخلط بينها، لا متوسط إجمالي فقط.
- أرقام، أسماء، كلمات إنجليزية وسط العربية، النفي، الأفعال، والأوامر.
- نسبة أخطاء المعنى الحرجة (مثل حذف «ما/مش/لا»، قلب رقم، أو اسم ملف).
- TTS: MOS بشري، وضوح النطق، طبيعية اللهجة، حفظ المصطلحات الإنجليزية والأرقام، زمن بدء الصوت، real-time factor، واستهلاك RAM/VRAM/CPU.
- تسجيل الحد الأدنى/المتوسط/المئين 95 للزمن واستهلاك الموارد على جهاز أساسي وآخر متقدم.
- ASR يعرض النص للمراجعة، ولا ينفذ أي أمر عالي الأثر قبل تأكيد مستقل.

## 6. مراحل الدمج

1. **Acceptance baseline:** جمع التسجيلات بإذن، تثبيت transcripts، وتشغيل Whisper الحالي.
2. **ASR challenger:** تشغيل QwenCleo كمرشح اختياري على جهاز مناسب؛ لا يستبدل Whisper حتى يجتاز الدقة/الزمن/الموارد/الخصوصية.
3. **Egyptian TTS challenger:** تجربة KemeTone للمقاطع المصرية، واختبار split/route مع Piper English؛ تقييم VoiceTut على GPU كخيار مختلط.
4. **Conversation turn-taking:** ضغط للتسجيل/إيقاف/إلغاء، اكتشاف نهاية الكلام، زمن انتظار واضح، ثم دراسة Full-duplex والمقاطعة بعد استقرار الحزم السابقة.
5. **Tool hand-off:** النص المستخرج يدخل الفهم المحلي، لكن parser/plan/approval/verification تبقى الحدود الحاسمة. لا ينفذ ASR النص مباشرةً كتعليمات ولا يتخطى الموافقات.
6. **Release gates:** تنزيلات مثبتة البصمة، إظهار تراخيص النماذج، إيقاف/حذف بيانات مؤقتة، واختبارات Windows يدوية.

## 7. بوابات القبول

- [ ] مصفوفة 4 لغات/تنوعات كاملة على مجموعة ذهبية مسجلة.
- [ ] قياس Whisper الحالي وإضافة نتائج منافس على نفس الملفات.
- [ ] اختيار ASR مثبت على أداء جهاز أساسي ومتقدم.
- [ ] صوت مصري مختبر بشريًا؛ لا يكفي وصف النموذج لنفسه بأنه Egyptian.
- [ ] العربية الفصحى والإنجليزية تستمران دون تراجع بعد إضافة الصوت المصري.
- [ ] المقاطع المختلطة تقسم دون فقد المصطلحات أو ترتيب الجملة.
- [ ] إلغاء STT يمسح الصوت والنص المؤقت ولا يرسل الطلب.
- [ ] لا تنفيذ أمر من transcript قبل مراجعته/مروره بنظام الفهم والموافقات.
- [ ] لا تسجيل دائم ولا رفع صوت صامت.
- [ ] كل الموارد مرخصة ومثبتة بالإصدار والبصمة.
