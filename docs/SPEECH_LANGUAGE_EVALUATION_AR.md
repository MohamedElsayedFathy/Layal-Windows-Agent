## 1. خط الأساس الموجود في Layal

- تسجيل يدوي من الميكروفون بموافقة واضحة، ثم WAV mono 16 kHz / 16-bit.
- Whisper.cpp multilingual base هو محرك STT المحلي الحالي، مع أرشيف تشغيل ونموذج مثبتين الحجم وSHA-256.
- تعرض نتيجة التفريغ للمراجعة قبل إرسالها إلى مسار المحادثة أو المهام؛ لا ينفذ ASR أمرًا ولا يتجاوز موافقات الأدوات.
- النطق المحلي الحالي عبر VoiceTut-TTS باستخدام Voice Design فقط، بإصدارات مصدر وأوزان مثبتة وبدون reference audio أو voice cloning.
- لا يوجد Piper في مسار TTS الإنتاجي الحالي. لا يُعتمد الصوت المصري أو الفصحى اعتمادًا نهائيًا قبل التقييم السمعي.
- مسار STT/TTS محلي دون cloud fallback. ولا يُرفع تسجيل للتقييم أو التدريب أو المشاركة الخارجية دون موافقة مستقلة ومحددة.
- لم تُجمع تسجيلات تقييم ذات transcripts بشرية معتمدة؛ لذلك لا توجد نتائج WER/CER أو MOS فعلية حتى الآن.

## 2. محركات الإنتاج والمرشحون — لا استبدال قبل الاختبار

| المهمة | المحرك/المرشح | الوضع الحالي | القرار |
|---|---|---|---|
| STT | Whisper.cpp multilingual base | محرك الإنتاج المحلي الحالي؛ النموذج والأرشيف مثبتا البصمة | يظل خط الأساس حتى قياسه على مجموعة ذهبية |
| STT challenger | QwenCleo-ASR | مرشح بحثي معلن لدعم المصرية والمزج، لكنه يحتاج Python وموارد أكبر | لا تنزيل ولا استبدال قبل مراجعة الإصدار والبصمة والترخيص والقياس على العينات نفسها |
| TTS | VoiceTut-TTS Voice Design | محرك الإنتاج المحلي الحالي؛ لا أصوات مرجعية ولا cloning | جودة المصرية/الإنجليزية والخلط تحتاج تقييمًا بشريًا؛ الفصحى استكشافية فقط |
| TTS مصري | KemeTone | مرشح بحثي للمصرية فقط، ولا يدعم المزيج اللاتيني داخل النموذج نفسه | لا اعتماد قبل حسم حقوق هوية الصوت/المتحدث ومراجعة revision وSHA-256 |
| TTS بديل | VoxCPM2 | مرشح POC مشروط؛ متطلبات GPU وحقوق بيانات التدريب ودعم المصرية لم تُحسم | لا تنزيل حتى إغلاق مراجعة المصدر والأمان والعتاد |

**ملاحظات القرار:**
- لا يُختار QwenCleo من نتائج الناشر وحدها؛ يجب إعادة قياسه على ملفات Layal نفسها وبنفس شروط Whisper.
- VoiceTut يستخدم Voice Design بوصف ثابت، ولا يسمح التكامل بتحميل أصوات مرجعية أو cloning. حقوق هوية الصوت والقبول البشري النهائي ما زالا pending.
- لا يُعامل إعلان دعم اللغة في بطاقة النموذج على أنه نتيجة جودة؛ يجب تقييم المصرية والفصحى والإنجليزية والخلط كلًّا على حدة.
- Piper أزيل من مسار TTS الإنتاجي؛ أي قياس تاريخي له يجب وسمه بأنه مرجع قديم وليس المحرك النشط.
- كل تنزيل جديد يحتاج إصدارًا/commit ثابتًا وبصمات SHA-256 وبيان ترخيص وحقوق مصدر واضحة.

## 4. مجموعة الاختبار النصية وطريقة تشغيل أداة القياس

الملف `tests/TestAssets/Speech/speech-reference-set.json` يحتوي 30 جملة نصية موزعة على المصرية والفصحى والإنجليزية والمزج بينها. لا يحتوي الملف على صوت، ولا يسجل نتائج افتراضية أو أرقام دقة غير مقاسة. كل حالة تبدأ بـ `hypotheses: {}`.

بعد جمع تسجيلات بموافقة صريحة، واعتماد تفريغ بشري لكل تسجيل، يمكن إضافة نتيجة كل محرك تحت مفتاح ثابت يصف اسم المحرك وإصداره، مع ربط الحالة بالتسجيل المحفوظ وفق سياسة الاحتفاظ والخصوصية. يجب تشغيل كل المحركات على التسجيلات نفسها، وعدم مقارنة نتائج مأخوذة من مجموعات مختلفة.

من جذر المستودع:

```powershell
python tools/evaluation/score_speech_transcripts.py --validate-only
python tools/evaluation/score_speech_transcripts.py --validate-only --check-audio-files
python tools/evaluation/score_speech_transcripts.py
python tools/evaluation/score_speech_transcripts.py --engine whisper_cpp_base
```

- `--validate-only` يتحقق من بنية الملف ويعرض عدد الحالات لكل تنوع دون حساب أي مقياس.
- `--check-audio-files` يضيف التحقق من وجود كل ملف WAV مسجل داخل مجلد `audio/` المحلي، ويرفض المسارات الخارجة منه أو روابط الملفات التي تهرب إلى خارجه.
- التشغيل العادي يحسب WER وCER ومعدل أخطاء الرموز الحرجة (النفي والأرقام) للحالات التي تحتوي على فرضية نصية للمحرك.
- المفتاح الموجود بقيمة نص فارغ يُحسب كحالة حذف كاملة، ولا يتم تجاهله.
- WER محسوب على الكلمات بعد التطبيع؛ CER محسوب على محارف Unicode بعد التطبيع مع استبعاد المسافات.
- التطبيع يزيل التشكيل والتطويل وعلامات الترقيم وبعض اختلافات الألف/الياء/الكاف؛ يجب الإبلاغ عن هذه القواعد مع أي نتيجة ومراجعة أخطاء النفي والأسماء والأرقام ومسارات الملفات يدويًا.

**لا توجد نتائج قياس حتى تضاف فرضيات من تشغيلات حقيقية.** ظهور رسالة أن الفرضيات غير موجودة ليس نجاحًا في الدقة، بل يعني أن مرحلة جمع/تفريغ التسجيلات لم تبدأ بعد.


## 4.1 بوابة إدخال التسجيلات — موافقة المتحدث ومراجعة التفريغ

تظل الحالات النصية الحالية صالحة كما هي، وتُعامل كـ `recordingStatus: not-recorded`. عند إضافة تسجيل جديد، أضف إلى الحالة الحقول التالية فقط بعد إتمام الإجراء فعليًا:

```json
{
  "recordingStatus": "recorded",
  "audioAsset": "audio/eg-001.wav",
  "speakerId": "spk-001",
  "consent": {
    "granted": true,
    "recordedAt": "2026-11-17T10:00:00Z",
    "scope": "research-evaluation"
  },
  "referenceReview": {
    "status": "pending"
  }
}
```

- ضع التسجيلات محليًا في `tests/TestAssets/Speech/audio/` بصيغة WAV؛ لا تضف التسجيلات الخام إلى Git أو PR.
- `speakerId` و`reviewerId` رموز مستعارة فقط؛ لا تضع أسماء أو بريدًا أو رقم هاتف أو بيانات تعريفية في manifest.
- لا تسجل `consent.granted: true` إلا بعد موافقة صريحة فعلية. الموافقة هنا لنطاق التقييم البحثي فقط، ولا تعني موافقة على التدريب أو النشر أو المشاركة الخارجية.
- يبدأ التفريغ البشري بحالة `pending`. بعد مراجعته مقابل الصوت، غيّرها إلى `approved` وأضف `reviewerId` المستعار ووقت المراجعة ISO-8601.
- لا تقبل الأداة فرضيات ASR لحالة مسجلة قبل اعتماد التفريغ البشري. ولا تحتسب حالة غير مسجلة على أنها اختبار صوتي.
- عند سحب الموافقة، أوقف استخدام التسجيل واحذفه من التخزين المحلي والنسخ التابعة وفق سياسة الاحتفاظ، ثم أزل مرجعه من manifest. لا تحتفظ ببيانات اتصال المتحدث داخل المستودع.

مثال اعتماد التفريغ:

```json
"referenceReview": {
  "status": "approved",
  "reviewerId": "rev-001",
  "reviewedAt": "2026-11-17T11:00:00Z"
}
```

تتحقق الأداة من صيغة المسار، وامتداد WAV، ومعرّفات المتحدث/المراجع المستعارة، وتسجيل الموافقة ونطاقها وتوقيتها، وحالة مراجعة النص. خيار `--check-audio-files` يفحص وجود الملفات فعليًا ويمنع اجتياز مسارات symlink التي تخرج من مجلد الصوت، ويتأكد من أن كل WAV هو PCM أحادي القناة 16 kHz / 16-bit.

## 5. مصفوفة التقييم الصوتي المطلوبة

لكل متحدث/متحدثة متطوع/ة وبموافقة واضحة، اجمع على الأقل 30–50 جملة لكل فئة أولية، ثم وسّعها إلى 100+ لكل فئة:

1. مصرية يومية: أسئلة، نفي، أفعال متصرفة، ضمائر، أرقام وأسماء أماكن.
2. فصحى: جمل رسمية، إعراب ونهايات، مصطلحات وقراءة نصوص.
3. إنجليزية: محادثة عامة، لهجات متعددة، كلمات تقنية وأسماء منتجات.
4. Mixed: إدخال أسماء التطبيقات/المصطلحات الإنجليزية داخل كلام مصري أو فصيح.
5. ظروف صوتية: هدوء، ضوضاء منزلية، ميكروفون قريب/بعيد، سرعة بطيئة وطبيعية وسريعة.
6. ظواهر الحوار: تردد، تصحيح الذات، مقاطعة، سؤال توضيحي، جملة غير مكتملة، حوار متبادل.

لا بد أن يحتوي كل ملف على transcript بشري معتمد، locale/variety، المتحدث برمز غير معرف، نوع الجهاز، ظروف التسجيل، مدة المقطع، وموافقة الاستخدام. لا تستخدم بيانات شخصية أو بيانات حساسة في مجموعة الاختبار.

## 6. المقاييس

- WER بعد تطبيع محافظ موثق، وCER للعربية.
- **Critical-token error rate** منفصل لأدوات النفي والأرقام؛ يحسب أخطاء الاستبدال والحذف بعد محاذاة Levenshtein حتى لا يخفي متوسط WER سقوط «مش/لا/not» أو تغيير رقم. تظل أسماء الأشخاص والملفات والمسارات بحاجة إلى مراجعة نوعية.
- قياس منفصل للمصرية والفصحى والإنجليزية والخلط بينها، لا متوسط إجمالي فقط.
- أرقام، أسماء، كلمات إنجليزية وسط العربية، النفي، الأفعال، والأوامر.
- نسبة أخطاء المعنى الحرجة (مثل حذف «ما/مش/لا»، قلب رقم، أو اسم ملف).
- TTS: MOS بشري، وضوح النطق، طبيعية اللهجة، حفظ المصطلحات الإنجليزية والأرقام، زمن بدء الصوت، real-time factor، واستهلاك RAM/VRAM/CPU.
- تسجيل الحد الأدنى/المتوسط/المئين 95 للزمن واستهلاك الموارد على جهاز أساسي وآخر متقدم.
- ASR يعرض النص للمراجعة، ولا ينفذ أي أمر عالي الأثر قبل تأكيد مستقل.

## 7. مراحل الدمج

1. **Acceptance baseline:** جمع التسجيلات بإذن، تثبيت transcripts، وتشغيل Whisper الحالي.
2. **ASR challenger:** تشغيل QwenCleo كمرشح اختياري على جهاز مناسب؛ لا يستبدل Whisper حتى يجتاز الدقة/الزمن/الموارد/الخصوصية.
3. **Egyptian TTS evaluation:** تقييم VoiceTut الإنتاجي أولًا، ومقارنته بمرشح KemeTone للمقاطع المصرية فقط بعد حسم حقوق الصوت؛ لا يوجد Piper في مسار الإنتاج.
4. **Conversation turn-taking:** ضغط للتسجيل/إيقاف/إلغاء، اكتشاف نهاية الكلام، زمن انتظار واضح، ثم دراسة Full-duplex والمقاطعة بعد استقرار الحزم السابقة.
5. **Tool hand-off:** النص المستخرج يدخل الفهم المحلي، لكن parser/plan/approval/verification تبقى الحدود الحاسمة. لا ينفذ ASR النص مباشرةً كتعليمات ولا يتخطى الموافقات.
6. **Release gates:** تنزيلات مثبتة البصمة، إظهار تراخيص النماذج، إيقاف/حذف بيانات مؤقتة، واختبارات Windows يدوية.

## 10. حدود الاستخدام والتحديث

- لا تُرفع تسجيلات المستخدمين أو بيانات المتحدثين إلى خدمات خارجية لأغراض التقييم إلا بموافقة صريحة منفصلة، وبعد مراجعة شروط الخدمة والاحتفاظ.
- لا تُستخدم بيانات من مصدر عام لمجرد إمكانية تنزيلها؛ يجب مراجعة الرخصة وحقوق التسجيلات/المتحدثين وشروط الاشتقاق وإعادة التوزيع.
- لا يتغير محرك الإنتاج بسبب نتيجة مقياس واحدة؛ يلزم نفس بروتوكول الاختبار، ومراجعة أخطاء نوعية، وقياس الموارد والخصوصية على أجهزة Windows المستهدفة.
- محرك الإنتاج الحالي يظل Whisper.cpp المحلي للتعرف وVoiceTut Voice Design للنطق؛ لا يُستبدل أي منهما قبل اجتياز جميع بوابات التقييم والقبول.
- تُحدّث هذه الوثيقة بعد كل مجموعة اختبار أو قرار نموذج مع تسجيل commit والنموذج والإصدار وظروف القياس.
