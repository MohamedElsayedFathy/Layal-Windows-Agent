# قائمة إغلاق الترخيص وحقوق الأصول — Layal

> **الغرض:** تحويل البنود القانونية المفتوحة إلى مهام قابلة للتتبع قبل أي إصدار عام أو تجاري.
>
> **الحالة عند إعداد القائمة:** لم تُحسم رخصة المشروع نفسه، ولم يُوثّق مصدر/إذن إعادة توزيع جميع أصول الشخصية والأيقونة. هذه القائمة ليست استشارة قانونية، ولا تمنح أي ترخيص أو حق استخدام. لا تُضف ملف `LICENSE` نهائيًا قبل تأكيد القرار من أصحاب الحقوق.

## بوابة الإصدار

- [ ] تحديد صاحب/أصحاب حقوق الكود والأصول، وتوثيق القرار ومصدر التفويض.
- [ ] اعتماد نموذج التوزيع المقصود: مفتوح المصدر، أو خاص/تجاري، أو نموذج آخر.
- [ ] اختيار شروط الترخيص ومراجعتها مع صاحب الحقوق/مستشار قانوني عند الحاجة.
- [ ] حسم حقوق كل أصل مرئي، أو استبدال الأصل الذي لا يوجد دليل كافٍ على حق توزيعه.
- [ ] مطابقة ملفات الترخيص والإشعارات مع الكود والأصول والاعتماديات الفعلية.
- [ ] تشغيل فحوص الترخيص وSBOM الخاصة بالإصدار وحفظ النتائج.
- [ ] تسجيل قرار نهائي موثق: **مسموح بالإصدار** أو **موقوف مع الأسباب**.

## 1. قرار ترخيص المشروع

- [ ] **تحديد صاحب القرار:** الاسم/الكيان المخوّل بالموافقة على ترخيص Layal، مع دليل التفويض عند تعدد المساهمين أو أصحاب الحقوق.
- [ ] **تحديد النطاق:** هل يشمل الترخيص الكود فقط، أم يشمل أيضًا الصور والأيقونات والوثائق والمواد التسويقية؟
- [ ] **تحديد نموذج التوزيع:** استخدام داخلي فقط، أو توزيع عام، أو توزيع تجاري، أو مساهمات خارجية.
- [ ] **اختيار الرخصة بعد القرار:** أمثلة الخيارات تشمل MIT وApache-2.0 والرخصة الخاصة/التجارية، لكن لا تُعتبر أي منها مختارة تلقائيًا. راجع التزامات كل خيار ومدى ملاءمته للمنتج.
- [ ] **مراجعة المساهمات:** التأكد من صلاحية إعادة ترخيص مساهمات الآخرين وعدم وجود اتفاقات أو شروط سابقة تتعارض مع القرار.
- [ ] **إضافة الملف المناسب:** بعد اعتماد القرار فقط، أضف `LICENSE` في جذر المستودع بالنص الرسمي الكامل وبيانات صاحب الحقوق والسنة الصحيحة.
- [ ] **تحديث الوثائق:** حدّث `README.md` و`README_AR.md` و`docs/PROJECT_LICENSE_STATUS_AR.md` و`licenses/PROJECT-LICENSE-STATUS.md` لتتطابق الحالة المعلنة في كل مكان.
- [ ] **تحديد حقوق العلامة التجارية:** توضيح ما إذا كان اسم Layal والشعار/الشخصية مسموحًا بإعادة استخدامهما بصورة مستقلة عن ترخيص الكود.

**دليل الإغلاق المطلوب:** قرار مكتوب من صاحب الحقوق، ونص الترخيص المعتمد، وcommit يضيف/يحدّث الملفات بعد الموافقة.

## 2. سجل مصدر وحقوق الأصول

لا يثبت وجود الملف في GitHub أو إنتاجه بأداة توليد صور أو قصّه من صورة أكبر ملكية حقوقه أو الإذن بإعادة توزيعه. يجب تسجيل المصدر الحقيقي والأدلة المتاحة لكل أصل.

سجل الأصول الفعلي موجود في `docs/ASSET_RIGHTS_REGISTER.csv`. نتائج تقصّي المنشأ والأدلة المتاحة موثقة في `docs/ASSET_PROVENANCE_FINDINGS_AR.md`. يحتوي على صف مستقل لكل أصل بصري حالي ومساره وحجمه ومعرّف Git blob في snapshot محدد، بالإضافة إلى حقول المصدر والمنشئ وصاحب الحقوق والترخيص والسماح بالتوزيع/التعديل والإسناد والأدلة والمراجع. جميع الحالات تبدأ بـ `UNVERIFIED` إلى أن تُملأ بالأدلة وتُراجع.

**تنبيه حول المعرّفات:** `git_blob_sha1` هو معرّف Git blob (SHA-1) لتعريف نسخة الملف في ذلك الـ snapshot، وليس SHA-256 لمحتوى الملف. لا تملأ حقل بصمة SHA-256 بالقيمة نفسها؛ احسب بصمة SHA-256 من الملف الأصلي عند الحاجة إلى تحقق سلامة مستقل.

### لكل أصل، سجّل البيانات التالية

- [ ] اسم الأصل ومساره وبصمته SHA-256.
- [ ] صانع الأصل وصاحب الحقوق، وأداة/نموذج الإنشاء وإصداره إن كان ذلك ذا صلة.
- [ ] الأصل المصدر أو رابط المصدر وتاريخ الحصول عليه.
- [ ] نسخة الترخيص أو إذن الاستخدام وإعادة التوزيع، بما في ذلك الاستخدام التجاري والتعديل، إن كان مسموحًا.
- [ ] أي شروط إسناد أو إشعار أو قيود على العلامة التجارية أو على مخرجات الأداة.
- [ ] مكان حفظ الدليل، مع تجنب تخزين أي بيانات اعتماد أو معلومات سرية في المستودع.
- [ ] موافقة صاحب الحقوق على الأصول التي أنشأها متعاقد/طرف آخر، إن انطبق ذلك.

إذا تعذر إثبات الحقوق، لا تعتبر الأصل مسموحًا للتوزيع تلقائيًا: احصل على إذن مكتوب، أو استبدله بأصل ذي شروط واضحة، أو احذف استخدامه قبل إصدار الحزمة.

## 3. الاعتماديات والإشعارات

- [ ] إنشاء SBOM من مخرجات الإصدار نفسها، وليس من قائمة يدوية قد تكون قديمة.
- [ ] التحقق من كل حزمة مباشرة ومتعدية ومكتبة/أصل مضمّن من اسم الإصدار ومصدره ورخصته.
- [ ] التأكد من أن نصوص الرخص وإشعارات حقوق النشر المطلوبة موجودة في حزمة التوزيع.
- [ ] مراجعة توافق شروط الاعتماديات مع نموذج الترخيص والتوزيع المقصود للمشروع.
- [ ] عدم اعتبار وجود `THIRD_PARTY_NOTICES.md` أو نجاح فحص آلي إثباتًا لحقوق أصول Layal الخاصة.
- [ ] تشغيل `tools/validate_licenses.py` وفحوص SBOM/التوزيع المعرّفة في CI، وحفظ سجلات التشغيل.
- [ ] مراجعة أي تنبيه أو استثناء يدويًا وتوثيق المبرر والمسؤول والموافقة.
