# دليل كتالوج تكاملات API في ليال

## ما الذي توفره الميزة؟

يتيح تبويب **تكاملات API** حفظ اتصالات مستقلة بتطبيقات كثيرة تستخدم HTTP REST/JSON. لا يوجد حد ثابت لعدد الاتصالات في واجهة التخزين؛ استخدم خانة البحث لتصفية القائمة بالاسم أو عنوان API أو التفاصيل. تظل الاتصالات محفوظة بعد إعادة تشغيل ليال داخل مخزن محمي بتشفير Windows DPAPI للمستخدم الحالي.

## إضافة اتصال جديد

1. افتح تبويب **تكاملات API** واضغط **إضافة اتصال جديد**.
2. اكتب **اسم التطبيق** و**عنوان API الأساسي (Base URL)**؛ كلاهما إجباري.
3. اختر طريقة المصادقة: بدون مصادقة، أو Bearer token، أو ترويسة مخصصة مثل `X-API-Key`. عندما تتطلب الخدمة مفتاحًا، أدخله في خانة المصادقة وليس في التفاصيل.
4. يمكن اختيار صورة محلية (PNG/JPEG/BMP/GIF/TIFF؛ حتى 5 MB). تنسخ ليال الصورة إلى مجلد بياناتها كي لا يعتمد العرض على بقاء ملف المصدر في مكانه.
5. يمكن إضافة معرّف نموذج وتفاصيل توثيق/نقاط نهاية اختياريين. لا تضع الأسرار داخل التفاصيل أو الترويسات غير السرية.
6. اضغط **حفظ الاتصال**. تُضاف الوصلة إلى القائمة وتُفرغ خانات النموذج تلقائيًا لتجهيز إدخال اتصال آخر. لتعديل اتصال موجود، حدده من القائمة، غيّر الحقول ثم احفظ.

يحافظ التخزين على الأسرار داخل ملف مشفر بـ DPAPI، ولا تُدرج مفاتيح المصادقة في وصف أداة API المرسل للنموذج. يمكن حذف اتصال بعد تأكيد المستخدم. يُطلب إذن محلي قبل كل طلب API من الوكيل، بما في ذلك GET؛ وقد تُرسل استجابة التطبيق إلى مزود الذكاء الاصطناعي المستخدم في المهمة.

## إعداد API الذي تستخدمه ليال

إذا كان لديك مزود نماذج متوافق مع OpenAI، يمكنك حفظ اتصال بمصادقة **Bearer**، وإدخال **Model ID**، ثم الضغط على **استخدام هذا كـ API ليال**. يلزم وجود عنوان أساسي صالح ومفتاح API ومعرّف نموذج. سيُحفظ هذا الاتصال بوصفه مزود ليال السحابي، وتُنسّق إعدادات عنوان المزود والنموذج والمفتاح معه في الاتجاهين: عند تعديل الملف النشط أو عند حفظ إعدادات المزود في تبويب الإعدادات.

**الذكاء الاصطناعي المحلي يظل هو الوضع الافتراضي.** تحديد مزود API لا يوقف وضع Ollama المحلي تلقائيًا؛ لاستخدام المزود السحابي، عطّل خيار الذكاء الاصطناعي المحلي في الإعدادات.

## حد مهم: مزود ليال ليس API عامًا مستضافًا منها

هذا الإعداد يحدد خدمة الذكاء الاصطناعي الخارجية التي تتصل بها ليال عند اختيار الوضع السحابي. تطبيق Windows المحلي لا ينشئ تلقائيًا خادم API عامًا أو مفتاحًا يمكن لبرامج أخرى استخدامه لاستدعاء ليال عن بُعد. تقديم API مستضافة خاصة بليال لبرامج أخرى يحتاج خدمة خلفية مستقلة، ومصادقة وصلاحيات، وتشغيلًا واستضافةً آمنين؛ وهذه ليست جزءًا من هذا التغيير.

## النطاق والقيود

- الموصل الحالي مخصص لواجهات HTTP REST/JSON وطرق GET وPOST وPUT وPATCH وDELETE.
- يدعم عدم المصادقة وBearer وCustom Header؛ ولا يعني ذلك دعم OAuth التفاعلي أو gRPC أو SOAP أو كل واجهات التطبيقات.
- عنوان Base URL يجب أن يستخدم HTTP أو HTTPS. استخدام HTTP مع بيانات دخول قد يكشفها على الشبكة؛ يظل HTTPS هو الاختيار الموصى به.
- كل طلب API يحتاج موافقة محلية مستقلة، ولا تعتبر ملاحظات التوثيق أو محتوى الرد تصريحًا لتنفيذ طلبات أخرى.
- البحث في القائمة يغطي الاسم والعنوان والتفاصيل ومعرّف النموذج، ولا يفحص مفاتيح المصادقة.
- صورة التطبيق اختيارية ويُخزّن مسار النسخة المحلية في ملف الاتصال المشفر.
