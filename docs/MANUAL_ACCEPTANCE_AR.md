# دليل القبول اليدوي — Layal / ليال

الغرض من هذا الدليل اختبار الميزات التي تحتاج Windows فعليًا. اجتياز CI يثبت أن النسخة بُنيت وأن الاختبارات الآلية نجحت؛ لكنه لا يثبت أن مزود الذكاء الاصطناعي أو التطبيق الخارجي أو الموقع الحقيقي عمل كما هو متوقع.

## 1. بيئة الاختبار

- Windows 10/11 x64 مع Microsoft Edge.
- استخدم أحدث Windows Release artifact من آخر GitHub Actions run ناجح على فرع `feature/approved-ui-automation-inspection`، أو ابنِ المشروع من المصدر على Windows.
- اضبط عنوان API ومُعرّف النموذج ومفتاحًا لمزود OpenAI-compatible يدعم tool/function calling.
- افتح إعدادات ليال وفعّل **السماح بفحص النوافذ وعناصر الواجهة وتنفيذ فعل واحد بموافقة**. هذا الخيار معطل افتراضيًا.
- لا تختبر ببيانات إنتاج أو كلمات مرور أو حسابات حساسة.

## 2. تشغيل تطبيق الاختبار المحلي

من مجلد المصدر على Windows، افتح Windows PowerShell ثم نفّذ:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Start-LayalUiAutomationSample.ps1
```

تظهر نافذة بعنوان `Layal UI Automation Sample`. التطبيق تجريبي لا يرسل البيانات لأي خادم ولا يحفظ محتوى حقل النص. زر الاختبار يغيّر رسالة الحالة محليًا فقط.

## 3. فحص عناصر نافذة Windows

1. اطلب من ليال فحص نافذة `Layal UI Automation Sample` باستخدام `inspect_window_controls`.
2. وافق على نافذة الموافقة المحلية، وراجع عنوان النافذة وبيانات العناصر.
3. تحقق من ظهور المعرّفين `layalSampleTextInput` و`layalSampleCheckBox` و`layalSampleActionButton`.
4. لا ينبغي أن يعرض التقرير قيمة حقل النص أو محتوى حقل كلمة المرور. قد لا يظهر حقل كلمة المرور ضمن قائمة العناصر أصلًا.

**معيار النجاح:** تعرض ليال metadata محدودة فقط، ولا تحدث أي ضغطة أو كتابة خلال الفحص.

## 4. اختبار إدخال نص آمن

اطلب من ليال استخدام `fill_ui_text` بهذه القيم:

- `window_title`: `Layal UI Automation Sample`
- `automation_id`: `layalSampleTextInput`
- `text`: `Layal text entry test`

تأكد من ظهور نافذة موافقة محلية تعرض العنصر والنص المراد إدخاله. ارفض المحاولة أولًا، ثم تحقق أن محتوى الحقل لم يتغير. كرر المحاولة ووافق؛ يجب أن يظهر النص في الحقل وأن تعرض رسالة الحالة عدد الأحرف. لا يضغط هذا الإجراء Enter ولا يرسل النموذج.

بعد ذلك اختبر المعرّف `layalSamplePasswordInput`. يجب رفض العملية وعدم تعديل حقل كلمة المرور؛ وقد يختلف نص الرفض بحسب ما إذا كان Windows يعرض العنصر بوصفه حقل كلمة مرور.

**معيار النجاح:** لا توجد كتابة قبل الموافقة؛ ورفض الموافقة لا يغير الحقل؛ ولا تقرأ ليال القيمة السابقة أو تعيدها ضمن نتيجة الأداة.

## 5. اختبار مربع اختيار واحد

اطلب من ليال استخدام `set_ui_checkbox` مع:

- `window_title`: `Layal UI Automation Sample`
- `automation_id`: `layalSampleCheckBox`
- `checked`: `true` ثم `false`

اختبر الرفض أولًا وتأكد من بقاء حالة مربع الاختيار كما هي، ثم وافق على كل تغيير على حدة. عند الموافقة فقط، ينبغي أن تتغير علامة الاختيار ورسالة الحالة المحلية. إذا كان المربع في حالة ثلاثية/غير محددة أو أصبح مخفيًا أو معطلًا، يجب رفض الإجراء بدل تخمين الحالة.

**معيار النجاح:** موافقة منفصلة لكل تغيير، وعدم تنفيذ أي تغيير بعد الرفض، وعدم الادعاء بأن تطبيقًا خارجيًا أكمل عملية أعلى مستوى لمجرد تغيّر حالة مربع الاختيار.

## 6. اختبار استدعاء زر واحد

اطلب من ليال تشغيل `click_ui_control` مع:

- `window_title`: `Layal UI Automation Sample`
- `control_type`: `Button`
- `automation_id`: `layalSampleActionButton`

تحقق من أن نافذة الموافقة تعرض الزر والنافذة الصحيحين. ارفض مرة ثم وافق مرة. عند الموافقة فقط يجب أن تتغير رسالة الحالة إلى `Button action observed locally`. هذا الاختبار لا يثبت نجاح تطبيق إنتاج، لكنه يثبت أن الزر التجريبي تلقّى الإجراء.

## 7. اختبار المتصفح المنفصل

استخدم موقعًا عامًا لا يحتوي على معلومات شخصية:

1. اطلب `browser_navigate` إلى `https://example.com/`، وراجع URL في الموافقة المحلية قبل المتابعة.
2. اطلب `browser_read_page`؛ راجع الموافقة لأن نص الصفحة وقوائم الروابط ستُرسل إلى مزود AI.
3. بعد قراءة عناصر الصفحة، استخدم `browser_click` فقط مع محدد CSS يطابق رابطًا أو زرًا واحدًا، ثم راجع موافقة جديدة. اختبر أيضًا رفض الموافقة وتأكد أن النقر لا يتم.
4. استخدم `browser_fill` لحقل بحث تجريبي غير حساس فقط. حقول كلمات المرور والملفات والحقول المخفية غير مدعومة.
5. أغلق جلسة Edge المخصصة وأعد تشغيل ليال؛ تحقق من أنها لا تحتاج ولا تستعمل ملف تعريف المتصفح اليومي أو جلسة تسجيل الدخول الخاصة به.

**معيار النجاح:** التنقل/القراءة/النقر/الكتابة كلّها تتطلب موافقة لكل فعل؛ المحدد الغامض يُرفض؛ ولا تعلن ليال نجاح الطلب الذي أرسلته للموقع دون ملاحظة دليل مناسب.

## 8. تسجيل نتيجة القبول

سجل في تقرير الاختبار:

- تاريخ الاختبار وإصدار Windows وSHA commit المختبَر.
- اسم مزود AI ونوع توافق tool calling من دون تسجيل أي مفتاح أو سر.
- نتيجة كل بند: Pass / Fail / Blocked، ورسالة الخطأ المختصرة إن وجدت.
- هل كان الرفض بلا أثر؟ وهل ظهر أي محتوى حقل قديم أو سر في سجل المهمة؟
- أي خلل في RTL/LTR أو في نافذة الموافقة أو خروج البرنامج.

لا تُحوّل متطلبات `LAYAL-017` أو `LAYAL-018` إلى «متحقق» قبل توثيق تشغيل فعلي. البناء ونجاح الاختبارات الآلية لا يغنيان عن هذا الدليل.

## 10. اختبار الشخصية العائمة

نفّذ الخطوات على Windows بعد نجاح CI، وسجّل ناجح/فاشل/لم يُختبر:

1. نقرة واحدة على الوجه تعرض ردًا تعبيريًا دون فتح الواجهة الرئيسية.
2. كرّر النقر؛ يجب أن تتنوع المشاعر والإيموجي وألا يتكرر الرد نفسه مباشرة.
3. اسحب الشخصية ثم أعد تشغيل التطبيق؛ يجب أن يبقى موضعها محفوظًا.
4. انقر مرتين بسرعة؛ يجب أن تفتح الواجهة الرئيسية.
5. حرّك المؤشر فوق الشخصية ثم خارجه؛ يجب أن تتبع العينان المؤشر وتعودا لوضع مريح.
6. اترك الشخصية في وضع الخمول لدقيقتين؛ يجب أن تنام بهدوء وتستيقظ عند المرور أو النقر.
7. اترك مهمة جارية أكثر من دقيقتين؛ لا ينبغي أن تنام ليال أثناء التنفيذ أو انتظار الموافقة.
8. عطّل الحركات من الإعدادات وتأكد من توقف الحركة الزخرفية مع استمرار الاستخدام.
9. اختبر قائمة الزر الأيمن: فتح، إخفاء، وخروج.

هذا الاختبار اليدوي ضروري؛ نجاح CI لا يثبت وحده سلوك نافذة WPF أثناء التشغيل.

## 11. اختبار المظهر الفاتح والداكن

1. شغّل ليال بوضع المظهر الفاتح، وتحقق من قابلية قراءة النصوص والحقول والقوائم والبطاقات وأزرار الحالة.
2. اضغط زر المظهر للتبديل إلى الداكن. تحقق من الخلفية والبطاقات والحدود وعناصر التنقل والحقول والتركيز وقوائم المهام ورسائل النجاح والتحذير والخطأ.
3. بدّل بين المظهرين عدة مرات بينما تتنقل بين الأقسام؛ لا ينبغي أن تبقى أجزاء رئيسية بلون ثابت غير مقروء أو يحدث استثناء موارد.
4. أعد تشغيل البرنامج. يجب أن يعود إلى السمة الأخيرة التي اخترتها.
5. اختبر العربية والإنجليزية مع كل سمة؛ يجب أن يبقى زر اللغة واتجاه RTL/LTR صحيحين وأن يكون نص الزر التالي واضحًا.
6. اختبر حالة اتصال ناجحة وفاشلة وحالة مهمة ملغاة؛ يجب أن تبقى ألوان الحالة مقروءة في المظهرين.
7. سجّل أي عنصر لا يتغير مع السمة أو يظهر بتباين ضعيف. هذا اختبار يدوي مطلوب بالإضافة إلى نجاح CI.
