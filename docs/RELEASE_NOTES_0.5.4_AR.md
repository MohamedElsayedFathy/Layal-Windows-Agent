# ملاحظات إصدار 0.5.4 — كتالوج تكاملات API

## الجديد

- كتالوج تكاملات API قابل للبحث بالاسم وعنوان API والتفاصيل ومعرّف النموذج، دون حد ثابت لعدد الاتصالات المحفوظة.
- جعل اسم التطبيق وعنوان API الأساسي حقولًا إجبارية، مع صورة محلية اختيارية ونسخة محفوظة داخل مجلد بيانات ليال، وتفاصيل استخدام اختيارية.
- تفريغ نموذج الإضافة تلقائيًا بعد حفظ اتصال جديد، مع دعم تحديد اتصال محفوظ وتعديله وحذفه بعد التأكيد.
- إمكانية اختيار اتصال Bearer متوافق مع OpenAI وله Model ID بوصفه مزود API السحابي الذي تستخدمه ليال. يبقى الوضع المحلي هو الافتراضي، وتظل إعدادات المزود السحابي اختيارية.
- مزامنة الملف المختار لـ API ليال مع عنوان المزود ومعرّف النموذج والمفتاح في إعدادات المزود؛ المفاتيح محفوظة في مخازن DPAPI المحمية.
- اختبارات لاختبار حفظ 100 اتصال مع البيانات الاختيارية، واختبار اختيار مزود واحد فقط لليال، ورفض مزود ليال بلا معرّف نموذج.

## الحدود المعروفة

- هذا الخيار يضبط مزود ذكاء اصطناعي خارجيًا تستخدمه ليال عند إيقاف وضع الذكاء الاصطناعي المحلي؛ لا ينشئ خدمة API عامة مستضافة من ليال.
- يتطلب الموصل REST/JSON؛ لا يضمن دعم كل البروتوكولات أو آليات OAuth.
- يلزم اختبار Windows الفعلي للصور، وتدفق الإضافة/التعديل، والاتصال بمزود متوافق مع OpenAI قبل اعتماد الإصدار.
- يُطلب إذن محلي لكل طلب API ينفذه الوكيل، وقد يرسل الرد إلى مزود الذكاء الاصطناعي النشط.
