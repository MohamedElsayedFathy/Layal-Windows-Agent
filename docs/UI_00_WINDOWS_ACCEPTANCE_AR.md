# قبول UI-00 العملي على Windows

## الغرض

يسجل هذا النموذج فحص UI-00 على جهاز Windows فعلي. تغييرات UI-00 البرمجية واختباراتها الآلية موجودة بالفعل؛ هذا النموذج لا يعيد تنفيذها ولا يثبت القبول بمجرد وجوده. املأ النتائج بعد تشغيل النسخة المحددة أدناه، وأرفق صورًا أصلية مرتبطة برقم التشغيل أو الـcommit.

## ملخص القبول

- حالة UI-00: **Fail جزئي / Pending**.
- العيب المرصود: موضع نافذة الشخصية المحفوظ منفصل عن النافذة الرئيسية؛ عند 922×602 حجب العنوان وزر سجل المحادثات، ثم حجب عنوان صفحة المهام بعد تحريك النافذة الرئيسية.
- فحوص غير مكتملة: 1380×900، DPI مختلف، شاشات متعددة، وتأكيد سلوك الإغلاق إلى Tray.
- الدليل: لقطات مرئية في جلسة CUA. لم تُرفع اللقطات إلى المستودع لأنها أظهرت سجل محادثة محليًا محفوظًا.
- القرار: **لا يُعتمد UI-00 بعد**؛ يلزم حسم تداخل الشخصية ثم إعادة الاختبارات الفاشلة.

### قواعد التسجيل

1. استخدم `Pass` أو `Fail` أو `Pending` لكل بند مع ملاحظة موجزة.
2. أرفق دليلًا فعليًا للنجاحات والإخفاقات؛ لا تعتبر تنفيذ الإجراء وحده نجاحًا.
3. لا تضع علامة `Pass` إذا لم يعمل التطبيق أو لم يتوفر إعداد الاختبار.
4. لاختبار DPI أو الشاشات المتعددة، سجّل الأجهزة والإعدادات الفعلية؛ إذا لم تتوفر فابقِ الحالة `Pending`.
5. بعد الإصلاح، أعد الفحوص المتأثرة على commit جديد وسجّل رقم commit الجديد.
