# تجربة تقنية للشخصية ثلاثية الأبعاد الحقيقية — PR #6

## الحالة والهدف

هذه التجربة تبدأ من `main` الحالي ولا تعيد دمج فرع PR #6 القديم. الهدف هو إثبات إمكانية تحميل **ملف نموذج ثلاثي الأبعاد فعلي** داخل نافذة الشخصية الشفافة، بدل اعتبار هندسة `Media3D` الإجرائية نموذجًا فنيًا نهائيًا.

لا يُعلن اكتمال الشخصية ثلاثية الأبعاد قبل وجود أصل قابل لإعادة التوزيع بترخيص موثق، وتحميله وتشغيله داخل التطبيق، واجتياز فحوص الأداء والتفاعل.

## بوابة اختيار الأصل

لا يُضاف نموذج إلى المستودع إلا بعد تسجيل:

- رابط المصدر واسم المؤلف/الجهة.
- نص الترخيص أو ملفه ورابطه، وتأكيد أن الترخيص يسمح بالاستخدام والتعديل وإعادة التوزيع ضمن طريقة نشر التطبيق.
- أي نسب مطلوب، وقيود الاستخدام أو إعادة التوزيع.
- بصمة الملف وتنسيقه وحجمه.
- مصدر مستقل يثبت أن الأصل هو الملف المرخّص نفسه.

**لا تستخدم نموذجًا من نتائج البحث أو مولّدًا خارجيًا لمجرد أنه يبدو مناسبًا؛ يجب التحقق من حقوقه قبل إدخاله.**

## نطاق التجربة

1. حصر خيارات عرض glTF/GLB المناسبة لتطبيق WPF الحالي على .NET 10 وWindows، مع فحص صيانة المكتبة والترخيص ومتطلبات GPU وحجم الاعتماديات.
2. اختيار نموذج صغير مرخّص يشتمل على هيكل تحريك إن أمكن؛ تسجيل المصدر والترخيص قبل إضافته.
3. إنشاء عارض تجريبي مع تحميل آمن: رسالة خطأ واضحة عند غياب الأصل أو فشل التحميل، وعدم تعطيل نافذة الشخصية الحالية.
4. تجربة دوران الرأس، الرمش، فتح/إغلاق الفم، وحركة الجسم الأساسية. إذا لم يدعم النموذج هذه الحركات، لا تُحاكَ على أنها حركات هيكلية حقيقية.
5. مقارنة الأداء والذاكرة مع الشخصية الحالية على نافذة شفافة، مع الحفاظ على النقر والسحب ومناطق النقر واللغتين.

## معايير القبول

- [ ] ترخيص الأصل ومصدره موثقان في المستودع.
- [ ] تحميل ملف GLB/glTF حقيقي في وقت التشغيل، مع معالجة فشل التحميل.
- [ ] نموذج مرئي في نافذة الشخصية الشفافة، وليس مجرد هندسة إجرائية أو لقطة ثابتة.
- [ ] إثبات حركات الهيكل المتاحة من النموذج، وتوثيق أي حركات غير مدعومة.
- [ ] استمرار النقر المفرد والسحب والنقر المزدوج وتمرير النقرات في المناطق الشفافة.
- [ ] تشغيل البناء والاختبارات الآلية على Windows CI دون تحذيرات أو أخطاء جديدة.
- [ ] اختبار Windows تفاعلي فعلي لـ DPI وتعدد الشاشات والأداء؛ لا تُستبدل هذه البوابة بلقطات `RenderTargetBitmap`.

## حدود التنفيذ

هذا الفرع هو مرحلة تجربة تقنية وتوثيق قرار. لا يغيّر الشخصية الافتراضية، ولا يحذف الـ rig الحالي، ولا يضمّن أصلًا مجهول الترخيص. لا تُفعّل الشخصية الجديدة افتراضيًا حتى تجتاز معايير القبول وتوجد آلية رجوع آمنة إلى الشخصية الحالية.
