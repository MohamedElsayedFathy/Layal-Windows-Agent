# Layal | ليال — تطبيق Windows أصلي

**الإصدار المصدري: 0.5.4 — وضع الذكاء الاصطناعي المحلي أولًا** — يعمل الشات والصوت المحليان افتراضيًا بعد موافقة المستخدم على تنزيل Ollama والنماذج الصوتية اللازمة؛ لا يُطلب مفتاح API لاستخدام الشات الأساسي أو التسجيل/النطق المحلي. يبقى المزود السحابي خيارًا في الإعدادات للمهام المتقدمة وتحليل الصور والتكاملات التي تحتاج API. راجع `docs/LOCAL_AI_SETUP_AR.md` للمتطلبات والتنزيلات والخصوصية.

الإصدار يحتفظ كذلك بواجهة Calm Light، والشخصية WPF العائمة، والواجهة العربية/الإنجليزية، ومحرك مهام متعدد الجولات، وأدوات Windows المحدودة، واستيراد Skills، وسجل محادثات/مهام وذاكرة محلية مشفّرة بـ Windows DPAPI.

هذه نسخة تطويرية وليست المنتج النهائي. أُضيف تكامل REST/JSON للتطبيقات الخارجية، ومرحلة أولى لأتمتة المتصفح عبر جلسة Microsoft Edge مستقلة، وفحص محدود لعناصر Windows وتنفيذ إجراء واحد بعد معاينة وموافقة محلية. لا تستخدم الجلسة ملفات تعريف الارتباط أو تسجيل الدخول من المتصفح المعتاد، ولا تعني نتيجة النقر أو الكتابة أن التطبيق المستهدف أكمل العملية. تتوفر الآن مرحلة أولية لفهم الصور التي يختارها المستخدم ولقطات الكاميرا الثابتة بعد الموافقة؛ لكنها تحتاج إلى قبول يدوي على جهاز Windows ومزود يدعم الرؤية. تتوفر كذلك مرحلة أولية لاكتشاف كاميرات ONVIF المحلية وفتح بث RTSP/RTSPS باستخدام بيانات دخول مصرح بها؛ ما زال بث الفيديو الخام إلى النموذج والتسجيل وتتبع الأجسام والتحكم العام بالماوس والكيبورد وMCP غير مكتمل، وحزمة CI الحالية غير موقعة وتحتاج إلى مراجعة الترخيص.

## الوقت والتاريخ والطقس

تحاول الصفحة الرئيسية تحديد الموقع التقريبي عبر Windows Location Service بعد موافقة المستخدم، ثم تعرض الوقت والتاريخ بحسب المنطقة الزمنية للموقع وبيانات الطقس من الإحداثيات. يجري تحديث الطقس كل 30 دقيقة مع زر للتحديث اليدوي. لا يحفظ التطبيق الإحداثيات، ويمكن إدخال مدينة يدوية إذا كان الوصول للموقع غير متاح. راجع `docs/CLOCK_WEATHER_AR.md`.

- تم تحديث GitHub Actions لتشغيل `dotnet test` بعد بناء Release، وحفظ نتائج TRX كـ artifact.
- بيئة التأليف المحلية لا تحتوي على .NET SDK؛ لذلك يعتمد تحقق البناء والاختبارات على GitHub Actions على Windows. راجع نتيجة التشغيل المرتبطة بآخر commit قبل اعتماد التعديل، واختبر التطبيق يدويًا لأن نجاح CI لا يثبت قبول واجهات Windows أو المواقع الفعلية.

- `python tools/package_source.py` ينشئ ZIP بإصدار المشروع ويستبعد مجلدات البناء والكاش والمخرجات المحلية، ثم يتحقق من الحزمة نفسها قبل إعلان نجاح الإنشاء.
- `tools/VERIFY-LAYAL.ps1` يفحص المصدر، ثم يستعيد الاعتماديات ويبني نسخة Release على Windows، ويحفظ سجل التحقق في `artifacts`.
- `.github/workflows/windows-build.yml` يشغّل الفحوص الساكنة والبناء والاختبارات على Windows عند رفع المصدر إلى GitHub، ثم يحفظ نتائج الاختبارات.
- يوجد الآن مشروع اختبارات C# مستقل في `tests/Layal.Tests`، لكن لا تُعد البوابة ناجحة إلا بعد أن ينفذ `dotnet test` بنجاح على Windows CI.

## الوظائف المنفذة في المصدر

### 1. سطح المكتب والشخصية
- مشروع WPF أصلي يستهدف `net10.0-windows`.
- نافذة شخصية بلا إطار وخلفيتها شفافة، قابلة للسحب، مع خيار البقاء فوق النوافذ، والإظهار/الإخفاء من منطقة الإشعارات، وحركات وتعابير أساسية.
- حفظ حجم الشخصية وموضعها وشفافيتها وخيارات الحركة في إعدادات المستخدم.
- واجهة أساسية بالعربية والإنجليزية وتغيير اتجاه الواجهة. يلزم اختبار RTL/LTR يدويًا لكل الشاشات.

### 2. مزود الذكاء الاصطناعي
- اختبار نقطة `/models` ومحادثات `/chat/completions` لمزود متوافق مع OpenAI API.
- مسار منفصل لاستدعاء الأدوات عبر `tools` و`tool_calls`؛ يجب أن يدعم المزود والنموذج هذه الميزة. إذا لم يدعمها النموذج، قد يفشل تشغيل المهام مع رسالة من المزود.
- لا يوجد عنوان AI افتراضي مرتبط بـ FreeLLM؛ في التثبيت الجديد يكون عنوان API ومعرّف النموذج فارغين حتى يختار المستخدم المزوّد بنفسه. تبقى الإعدادات المحفوظة مسبقًا كما هي. يقبل محرك النموذج في هذا الإصدار واجهة chat/tool calling المتوافقة مع OpenAI؛ أي مزوّد ببروتوكول مختلف يحتاج إلى محول مناسب.
- مفتاح API محفوظ بتشفير Windows DPAPI للمستخدم الحالي، ولا يُكتب في ملف الإعدادات النصي.
- حالة "تم اختبار الاتصال" مرتبطة بالجلسة الحالية ولا تُعد ضمانًا بأن الخدمة ستظل متاحة لاحقًا.

### 3. محرك المهام والأدوات
- حلقة وكيل بحد أقصى 8 جولات نموذج و12 استدعاء أداة لكل مهمة.
- سجل مؤرخ لأحداث المهمة، حالة نهائية، حفظ آخر المهام محليًا بتشفير DPAPI، وإيقاف الطلب الجاري.
- كل أداة معلنة بمخطط JSON، والأدوات غير المعروفة تُرفض.
- الأدوات المتاحة:
  - `get_current_time` و`get_system_info` و`get_workspace_info`.
  - `list_workspace_files` لعرض عناصر المجلد المحدد فقط.
  - `read_text_file` لقراءة امتدادات نصية مسموحة وبحد 256 KB، مع موافقة لأن المحتوى سيُرسل إلى المزود.
  - `create_text_file` لإنشاء ملف نصي جديد حتى 100 KB داخل مساحة العمل، دون استبدال ملف موجود، وبعد موافقة.
  - `replace_text_in_file` لاستبدال مقطع فريد في ملف UTF-8 حتى 512 KB، بعد معاينة وموافقة، مع نسخة احتياطية.
  - `open_notepad` و`open_url`، بموافقة؛ عناوين URL محصورة في HTTP/HTTPS.
  - `run_dotnet_build` و`run_dotnet_test` على ملفات `.sln` أو `.csproj` داخل مساحة العمل، بتكوين Debug/Release، وموافقة ومهلة 120 ثانية. البناء والاختبارات قد ينفّذان كودًا من المشروع ويستعيدان حزمًا؛ شغّلهما فقط على مشروع موثوق.
  - `get_open_window_titles` و`activate_window`: معطلان وظيفيًا حتى تفعيل خيار قراءة عناوين النوافذ في الإعدادات؛ مشاركة العناوين مع المزود تتطلب موافقة منفصلة.
  - `search_memory` لملاحظات الذاكرة، بعد موافقة قبل مشاركة المطابقات مع المزود، و`save_memory` لحفظ ملاحظة محلية مشفّرة بعد موافقة.
- لا يوجد تنفيذ PowerShell/CMD عام، ولا تحكم شامل بالماوس/الكيبورد، ولا التقاط شاشة في هذا الإصدار.

### 4. مساحة العمل وتعديل الملفات
- الجذر الافتراضي: `%USERPROFILE%\Documents\LayalWorkspace`.
- أدوات الملفات ترفض المسارات المطلقة و`..` والخروج عن مساحة العمل، وتفحص وجود نقاط إعادة توجيه/روابط رمزية على المسار.
- قراءة الملفات مقتصرة على امتدادات مذكورة في `AgentToolExecutor.cs` وبحدود حجم.
- إنشاء ملف يتطلب أن يكون المجلد الأب موجودًا داخل مساحة العمل؛ لا يستبدل الملفات الموجودة.
- استبدال النص يتطلب أن يظهر النص القديم مرة واحدة بالضبط، ويتحقق من عدم تغيير الملف بعد المعاينة، وينشئ نسخة في `.layal-backups`.
- `dotnet build` و`dotnet test` محدودان بملف Solution/Project داخل مساحة العمل، لكن هذه الأوامر نفسها قد تنفذ targets من المشروع؛ لذلك الموافقة ضرورية.

### 5. مدير المهارات — ZIP وGitHub
- استيراد ZIP والتحقق من وجود `SKILL.md` وترويسة YAML وحقلي `name` و`description`.
- استيراد من GitHub العام بواسطة رابط مستودع أو `tree` لمجلد أو `blob` لملف `SKILL.md`.
- المستورد ينزّل أرشيفًا عامًا من GitHub، ثم يعيد حزم المجلد الذي يحتوي `SKILL.md` فقط. لا يستخرج الحزمة إلى مجلد التشغيل ولا يشغّل السكربتات.
- الحدود: 50 MB للأرشيف المضغوط، 10 MB إجماليًا للمجلد المستورد، 200 ملف، و5 MB لكل ملف. يجب أن يكون `SKILL.md` في جذر مجلد المهارة المحدد.
- فروع GitHub ذات الاسم البسيط مثل `main` و`master` مدعومة؛ أسماء الفروع التي تحتوي `/` غير مدعومة حاليًا. المستودعات الخاصة غير مدعومة.
- يمكن اختيار حتى 3 مهارات من القائمة لإرفاق محتوى `SKILL.md` كمراجع غير موثوقة للمهمة الحالية. لا يتم تشغيل سكربتات المهارات، ولا تعتبر تعليماتها تصريحًا بتجاوز سياسة الأمان.
- تعارض الاسم يتطلب موافقة صريحة على الاستبدال.

### 6. الذاكرة وسجل المحادثات
- ملاحظات محلية: إنشاء، تعديل، بحث، حذف، وتصدير JSON.
- محتوى الذاكرة وسجل المحادثة وسجل المهام محفوظ بتشفير DPAPI المرتبط بحساب Windows الحالي.
- البحث في الذاكرة بواسطة الوكيل يطلب موافقة قبل مشاركة الملاحظات المطابقة مع AI.
- هناك فحوص نمطية بسيطة لمنع بعض الأسرار الشائعة داخل الملاحظات؛ هذه ليست كاشف أسرار كاملًا. لا تحفظ كلمات مرور أو مفاتيح API في الذاكرة.
- تصدير الذاكرة إلى JSON ينتج ملفًا **غير مشفر** ويعرض تحذيرًا قبل التصدير.

### 7. تكاملات التطبيقات الخارجية عبر API

- أُضيف تبويب **تكاملات API** ككتالوج قابل للبحث لإضافة عدد كبير من اتصالات REST/JSON. الاسم وعنوان API الأساسي إجباريان؛ الصورة والتفاصيل اختياريان. بعد إضافة اتصال جديد يظهر في القائمة وتُفرغ الخانات لإضافة التالي. يمكن تعيين اتصال Bearer متوافق مع OpenAI وله Model ID باعتباره **API المزود السحابي الذي تستخدمه ليال**؛ تعديل هذا الملف يحدّث إعدادات المزود السحابي في الإعدادات، مع بقاء الذكاء الاصطناعي المحلي هو الافتراضي. هذا لا ينشئ خادم API عامًا مستضافًا من ليال. راجع [دليل كتالوج API](docs/API_CATALOG_AR.md).
- يدعم الإصدار واجهات HTTP REST/JSON بطرق `GET` و`POST` و`PUT` و`PATCH` و`DELETE`، مع مصادقة بدون مفتاح، أو Bearer token، أو ترويسة مخصصة مثل `X-API-Key`.
- كل اتصال يحتوي اسمًا، وBase URL، وطريقة مصادقة، ومسار اختبار `GET` اختياريًا، وملاحظات API/نقاط النهاية التي تساعد ليال على معرفة كيفية استخدام التطبيق.
- ملفات تعريف الاتصالات، بما فيها أسرار المصادقة، محفوظة داخل مخزن JSON مشفّر بـ Windows DPAPI في حساب Windows الحالي؛ لا تُكتب مفاتيح التطبيقات في `settings.json` أو في وصف الأداة المرسل للنموذج.
- زر **اختبار API** يرسل `GET` إلى مسار الاختبار ويعرض كود HTTP ومقتطفًا من الرد. في تبويب المهام يمكن لليال استخدام أداة `call_app_api`؛ تظهر موافقة محلية قبل كل طلب، بما في ذلك `GET`، ويُرسل رد API إلى مزود الذكاء الاصطناعي.
- يجب إدخال ملاحظات توثيق من دون أسرار؛ وتظل الملاحظات مرجعًا غير موثوق. الطلبات محصورة تحت Base URL الذي تم إعداده، ويُحدد حجم جسم الطلب والرد. لا تُتبع إعادة التوجيه HTTP تلقائيًا.
- هذا موصل REST/JSON عام، وليس وعدًا بدعم كل بروتوكول ومخطط مصادقة. OAuth التفاعلي وتجديد رموزه، وgRPC وSOAP، والبروتوكولات الخاصة، قد تتطلب محولًا مخصصًا. اتصالات HTTP غير المشفرة مع مصادقة تعرض تحذيرًا قبل كل طلب.

### 8. أتمتة المتصفح — مرحلة أولى

- أُضيفت أدوات `browser_navigate` و`browser_read_page` و`browser_click` و`browser_fill` عبر Chromium DevTools Protocol داخل Microsoft Edge بجلسة مستخدم منفصلة في `%LOCALAPPDATA%\Layal\BrowserProfile`.
- يستخدم الربط منفذ DevTools عشوائيًا على loopback فقط، ولا يتصل بملف المستخدم الخاص بمتصفح Edge المعتاد أو يستورد جلسات تسجيل الدخول الخاصة به. يمكن إعادة الاتصال بالجلسة المخصصة إذا كانت ما زالت تعمل.
- التنقل والقراءة والنقر وإدخال النص تتطلب موافقة محلية منفصلة. قراءة الصفحة ترسل العنوان والنص الظاهر (حد أقصى 20,000 حرف) وقوائم محدودة من الروابط والأزرار والحقول إلى مزود الذكاء الاصطناعي.
- النقر والكتابة يستخدمان محدد CSS يطابق عنصرًا واحدًا ظاهرًا؛ تتم إعادة التحقق من التبويب والعنصر بعد الموافقة. يمنع browser_click أزرار إرسال/إعادة ضبط النماذج وكل عنصر داخل نموذج HTML أو مرتبط به؛ حضّر الحقول باستخدام browser_fill ثم أرسل النموذج يدويًا من المتصفح. قد يظل معالج JavaScript لزر مستقل مسموح قادرًا على التنقل أو تغيير بيانات بعيدة، لذا راجع كل موافقة بعناية. الكتابة في حقول كلمة المرور والملفات والحقول المخفية غير مدعومة. تقتصر الروابط القابلة للنقر على HTTP/HTTPS.
- هذا إصدار أولي: لا يشمل رفع/تنزيل الملفات، ولا التحكم العام في ملفات تعريف المتصفح العادي أو جلسات تسجيل الدخول، ولا التصفح البحثي الموثق بالمصادر. يلزم اختبار يدوي على Edge قبل اعتبار التشغيل الفعلي مقبولًا.

### 9. التحكم الآمن في عناصر Windows — مرحلة أولى

- تستخدم `inspect_window_controls` لقراءة بيانات وصفية محدودة فقط، من دون قيم الحقول أو لقطات شاشة.
- تستخدم `click_ui_control` لاستدعاء `InvokePattern` على زر/رابط/عنصر قائمة مدعوم واحد ذي `AutomationId` فريد، مع موافقة جديدة قبل كل إجراء.
- تستخدم `fill_ui_text` لتعيين قيمة حقل `Edit` واحد باستخدام `ValuePattern.SetValue`. تُعرض معاينة النص في نافذة الموافقة المحلية، ولا تُقرأ القيمة القديمة أو تُرسل في نتيجة الأداة.
- يُرفض الحقل إذا كان كلمة مرور، أو للقراءة فقط، أو معطلًا، أو خارج الشاشة، أو غير فريد. يعاد التحقق من النافذة والعملية والحقل بعد الموافقة؛ حد شجرة الواجهة 400 عنصر ومهلة انتظار 8 ثوانٍ.
- لا يرسل هذا الإصدار ضغط Enter أو اختصارات ولا يضغط إحداثيات ولا يلتقط الشاشة ولا يثبت نجاح نتيجة التطبيق. اختبار القبول اليدوي على تطبيق تجريبي ما زال مطلوبًا.

## ما لم يُنفذ بعد

- التعرف على الكلام STT والرد الصوتي TTS بالعربية، واللهجة المصرية، والإنجليزية، واكتشاف اللغة تلقائيًا.
- التحكم العام بالماوس والكيبورد وإحداثيات الشاشة والتقاط الشاشة غير منفذ. الموجود حاليًا محدود بفحص عناصر UI Automation، واستدعاء إجراء واحد لزر مدعوم، وإدخال نص في حقل `Edit` واحد محدد بـ `AutomationId` فريد بعد موافقة محلية.
- البحث المتقدم وتنزيل/رفع الملفات عبر المتصفح، وإدارة التبويبات والأطر المعقدة وتسجيل النتائج بمصادر موثقة لم تُنفذ بعد. `open_url` يفتح المتصفح الافتراضي فقط؛ أدوات `browser_*` تستخدم جلسة Edge مستقلة خاصة بليال.
- بث الفيديو الخام إلى نموذج AI، فك الترميز المستمر للتحليل، اكتشاف الأجسام/تتبعها، التسجيل والتنبيهات، والمسح المكاني ثلاثي الأبعاد. للاستخدام الأولي لكاميرات ONVIF/RTSP المحلية راجع `docs/VISION_AR.md`.
- تكامل MCP فعلي، ذاكرة دلالية/RAG، SQLite ومخططات ترحيل، وتدريب/fine-tuning للنماذج.
- أُضيف في هذا الفرع مسار تجريبي لمثبّت Inno Setup وحزمة Windows ذاتية التشغيل وSBOM وبصمات SHA-256، مع اختبار دورة التثبيت في CI؛ ما زال نجاح المسار والقبول على جهاز نظيف مطلوبين. التوقيع الرقمي ومراجعة التراخيص لم يكتملَا.
- توجد اختبارات C# للمكونات المحددة؛ تغطية واجهة WPF والأجهزة الحقيقية ما زالت تتطلب اختبارات قبول إضافية.

## المتطلبات والتشغيل

- Windows 10/11 x64.
- .NET 10 SDK.
- اتصال إنترنت لاختبار مزود سحابي أو استيراد مهارة من GitHub العام.

1. ثبّت [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).
2. فك ضغط الحزمة في مجلد ثابت.
3. شغّل `BUILD-LAYAL.bat` لبناء/نشر Release، أو `START-LAYAL.bat` للتشغيل من المصدر.
4. من تبويب الإعدادات، أدخل عنوان API ومفتاحًا ومعرّف النموذج. اختبر الاتصال أولًا.
5. لإنشاء مهمة، افتح تبويب **المهام** واكتب هدفًا بالعربية أو الإنجليزية. قد يعرض الوكيل طلب موافقة قبل أي أداة ذات أثر. اختبر ذلك أولًا بمهمة قراءة بسيطة مثل `get_current_time` أو `list_workspace_files`.
6. عند بناء/اختبار مشروع، ضع ملف `.sln` أو `.csproj` الموثوق داخل `Documents\LayalWorkspace`، ثم وافق فقط بعد مراجعة المسار والأمر.
7. في تبويب المهارات، استورد حزمة ZIP أو رابط GitHub عام يحتوي على `SKILL.md`. حدد حتى 3 مهارات لتزويد المهمة بمراجعها النصية.
8. استخدم تبويب الذاكرة لإدارة الملاحظات المحلية. لا تصدّرها إلا إذا كنت تقبل أن يكون ملف JSON الناتج غير مشفّر.
9. لاختبار التحكم الآمن في تطبيقات Windows، راجع `docs/MANUAL_ACCEPTANCE_AR.md` وشغّل `tools/Start-LayalUiAutomationSample.ps1` على Windows. ابدأ بتجربة رفض الموافقة، ثم اختبار حقل النص التجريبي وزر الاختبار.

## التحقق وحدوده

تم فحص XAML كـ XML، والتأكد ساكنًا من أن معالجات أحداث XAML تشير إلى أسماء methods موجودة، وفحص بعض خصائص الكود والمجلدات. **لم يتم تشغيل `dotnet build` أو الاختبارات في بيئة إعداد الحزمة** لأن .NET SDK غير متوفر فيها. اجتاز Windows CI البناء والاختبارات الآلية في تشغيل سابق؛ راجع نتيجة أحدث commit قبل الاعتماد. لا يغني CI عن اختبار التصفح وأتمتة Windows يدويًا على الجهاز المستهدف.
- `docs/MANUAL_ACCEPTANCE_AR.md` يحتوي قائمة قبول تشغيل Windows لأتمتة المتصفح وWindows UI Automation، و`tools/Start-LayalUiAutomationSample.ps1` يشغّل نافذة WPF تجريبية قابلة للتخلص منها.

ابدأ بـ `BUILD-LAYAL.bat`. إذا فشل البناء، احتفظ بمخرجاته الكاملة؛ أصلح أخطاء البناء قبل اختبار الأدوات أو إعطاء الوكيل صلاحيات أوسع.

## التحقق قبل كل نسخة

1. شغّل `python tools/validate_project.py`.
2. أنشئ حزمة المصدر عبر `python tools/package_source.py`؛ سيتولى فحص ZIP الناتج تلقائيًا.
3. على Windows مع .NET 10 SDK وPython 3، شغّل `powershell -ExecutionPolicy Bypass -File .\tools\VERIFY-LAYAL.ps1`.
4. راجع `docs/MASTER_REQUIREMENT_REGISTER_AR.md`، ولا تغيّر حالة أي وظيفة إلى «متحقق» دون دليل اختبار فعلي.
5. اختبر يدويًا الوظائف التي تتطلب أجهزة أو مزودًا حقيقيًا: النافذة العائمة، AI provider، الموافقات، الصوت، وتحليل الصور/الكاميرا الثابتة.


## تحديث: جلسات المحادثات وتفاعلات الشخصية

- **محادثة جديدة:** تنشئ جلسة مستقلة وتحافظ على الجلسة السابقة في قائمة اختيار المحادثات.
- **استرجاع المحادثات:** اختر محادثة محفوظة من القائمة لاستكمالها، ويظل السياق خاصًا بتلك الجلسة.
- **مسح السجل المحفوظ:** يطلب تأكيدًا قبل حذف كل جلسات المحادثة محليًا؛ ثم ينشئ جلسة فارغة جديدة.
- **ترحيل السجل القديم:** عند الترقية، يُنقل سجل المحادثات السابق إلى مخزن الجلسات المحلي المشفر chat-sessions.dpapi.
- **فقاعات الإيموجي:** حالات مثل الفضول والتفكير والتخطيط والبحث والقراءة والبرمجة واستخدام الأدوات والاستماع والنجاح والتحذير والخطأ لها رموز متعددة. تظهر الفقاعة مع تغيّر الحالة، وتصعد وتتلاشى خلال قرابة 2.2 ثانية.
- تؤثر الحركات فقط عند السماح بالحركات في إعدادات الشخصية، ولا تعني الإيموجي بحد ذاتها أن المهمة نجحت؛ حالة المهمة وسجل الأدوات هما المرجع.
- اختبر هذه التغييرات من Windows CI ثم على الجهاز الفعلي قبل اعتبارها مكتملة.


## إصلاحات بناء على تجربة المستخدم

- **رياكشنات أكثر تنوعًا:** توسيع مجموعات الرموز المرتبطة بحالات الشخصية لتضم عشرات الخيارات عبر حالات الفضول والتفكير والتخطيط والبحث والبرمجة والاستماع والنجاح والخطأ وغيرها. يمكن إظهار رياكشن جديد عند تكرار الحالة مع حماية من التكرار السريع.
- **إيموجي ملوّنة:** إضافة `Emoji.Wpf` لاستخدام عرض متجهي يدعم الألوان في WPF بدل الاعتماد على إخراج الخط أحادي اللون.
- **هوية تصلح لمنتج تجاري:** لم تعد التعليمات تفترض أن المستخدم هو مطوّر ليال أو مالكها؛ تُستخدم معلومات موثقة عن المنتج إن وفرتها الواجهة، وإلا تعترف ليال بعدم امتلاك معلومة مؤكدة.
- **نسخ المحادثات:** زر لنسخ المحادثة كاملة وقائمة سياقية لنسخ رسالة منفردة، مع إشعار واضح بنتيجة النسخ.

هذه التعديلات تُعدّ موجودة في المصدر فقط إلى أن ينجح بناء Windows والاختبارات، ثم تُختبر الألوان وسلوك النسخ يدويًا على جهاز فعلي.


## تحسين سرعة المحادثة وتعابير الوجه

- أضيف مسار `ChatStreamAsync` لاستهلاك SSE وعرض أجزاء الرد أثناء وصولها، مع fallback إذا أعاد المزوّد JSON عاديًا بدل stream.
- يعيد بناء سياق كل طلب على آخر 14 رسالة بميزانية 12000 حرف افتراضيًا؛ سجل المحادثة الكامل يظل محفوظًا محليًا، لكن القديم لا يُعاد إرساله كله في كل طلب.
- أضيفت اختبارات للسلوك المتدفق وبديل JSON ولمُنشئ السياق المحدود.
- إعادة استخدام `HttpClient` في التطبيق لتفادي إهدار connection pools بين طلبات الشات المتتابعة.
- تعابير وجه إضافية: الترحيب والفرح والضحك والحب والخجل والغمزة والمفاجأة والحيرة والحزن والقلق والفخر والغضب والملل والمرح، مع إعادة ضبط التعبير المؤقت.
- يمكن تجربة بعض التعبيرات مباشرةً بطلبات مثل «اعملي غمزة» أو «وش مفاجأة». اختيار التعبير اللغوي تقريبي ولا يستنتج الحالة النفسية للمستخدم.
- لا يُعد تحسّن الزمن الفعلي مثبتًا حتى التجربة مع موفّر AI الفعلي؛ streaming يحسّن ظهور الرد تدريجيًا إذا كان الخادم يرسل الأجزاء فورًا، لكنه لا يغيّر سرعة توليد النموذج نفسه.
